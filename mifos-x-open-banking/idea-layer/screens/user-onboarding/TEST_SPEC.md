## TC-ONB-001 — Intro screen renders the hero, headline, body, trust chips and continue button

**Priority:** critical · **State:** intro

- **Given** The app launches unauthenticated; `AuthGraphRoute` starts at `IntroRoute`
- **When** `IntroScreen` composes
- **Then**
  - The `OnboardingHeroIllustration` renders
  - Headline renders from `{strings.user_onboarding.intro_headline}`
  - Body copy renders from `{strings.user_onboarding.intro_body}`
  - Two `AssistChip`s render: `{strings.user_onboarding.fapi_chip}` and `{strings.user_onboarding.fca_chip}`
  - A single continue button renders from `{strings.user_onboarding.intro_continue}`

## TC-ONB-002 — Continue navigates to the login screen

**Priority:** critical · **State:** intro

- **Given** `IntroScreen` is displayed
- **When** User taps the continue button
- **Then**
  - `onContinue` fires `navController.navigate(LoginRoute)`
  - The login screen stages the account-access-consent and renders the permission list

---

## TC-ONB-003 — The screen holds no state and performs no I/O

**Priority:** normal · **State:** intro

- **Given** `IntroScreen` is displayed
- **When** The screen composes and recomposes
- **Then**
  - No ViewModel is resolved — the composable takes only `onContinue` and a `Modifier`
  - No network call is made and nothing is persisted
  - There is no loading, error or empty state to reach

This is a **negative-space test** and worth keeping. `UserOnboardingViewModel` was removed in the
2026-07-28 source sync precisely because the screen needs no state; this scenario is what stops it
being reintroduced by accident.

---

## TC-ONB-004 — Intro is skipped on the re-consent path

**Priority:** normal · **State:** intro

- **Given** An authenticated user re-authorises from `consent-list` or `consent-detail`
- **When** The re-consent flow starts
- **Then**
  - Navigation targets `LoginRenewRoute`, not `IntroRoute`
  - `IntroScreen` is never composed — `LoginRenewRoute` exists precisely to skip onboarding

Routing coverage, not rendering coverage: it asserts where the user does **not** go. Sending a
returning customer back through first-run onboarding to re-approve a consent is the regression
this guards.
