## Overview

The signed-in member's own loan list (member role, per-group). On mount it loads all of the
member's loans — active, pending, closed — from Fineract `GET /self/loans?associations=repaymentSchedule`
scoped to the authenticated self-service client. Reads are offline-first: a SQLDelight `loans`
cache is served stale-while-revalidate (180 s TTL) and revalidated over the Fineract REST client
when `cmp-network-monitor` reports connectivity. Filtering by `LoanStatusFilter` (All / Active /
Closed) and expand-to-reveal of each loan's repayment schedule are both pure client-side state
transitions — the repayment schedule is pre-fetched on mount, so no additional network call fires.
Overdue loans show a warning icon and error-colored next-repayment text. A FAB (and empty-state
CTA) navigates to `loan-request`. No writes. Covers FR-016.

**Acceptance Criteria:**

- AC1: On mount call `get_self_loans(associations="repaymentSchedule")`; on success with loans show
       Content, on success with zero loans show Empty, on error show Error.
- AC2: Filter chips (ALL / ACTIVE / CLOSED) filter the already-loaded list client-side — no API call.
- AC3: Tapping a loan card toggles `selectedLoanId` to expand/collapse its repayment schedule (pure
       state, schedule pre-fetched).
- AC4: Active loans show a next-repayment row; overdue loans render a warning icon + error-colored text.
- AC5: Status chip is color-coded (active=primaryContainer, pending_approval=secondaryContainer,
       closed=surfaceVariant, overdue=errorContainer).
- AC6: FAB is visible only when `loans.isNotEmpty()`; empty state provides the request CTA. Both
       navigate to `loan-request` forwarding `clientId`.
- AC7: Pull-to-refresh invalidates cache and re-fetches; offline serves the SQLDelight cache; 401 →
       Unauthorized (session expired).

## Designed UX Reference

- **Stitch prompts:** `idea-layer/screens/personal-loans/prompts/`
- **Preview HTML:** `idea-layer/screens/personal-loans/preview/`
- **Design conformance:** A horizontally scrolling single-select filter chip row (All / Active /
  Closed) sits under the primary top bar. Each loan card (surface, lg radius, elevation 2) shows the
  product name in titleMedium with a color-coded status chip, the outstanding principal in
  headlineSmall, and — for active loans — a next-repayment row that turns error-colored with a
  `warning` icon when overdue. Tapping the card rotates the chevron and reveals a repayment-schedule
  column of period rows, each with a filled/empty status circle and a per-period amount. An extended
  secondary FAB "Request Loan" sits bottom-end. Empty state uses a `money` icon with a request CTA.
