The screen loads entirely from the local SQLDelight `sync_queue` (no network read). `batch_sync` is
the only network call — invoked by Sync Now (all pending), per-item Retry, or the `SyncManager`
background job, and only when `cmp-network-monitor` reports online.

## Request / Response Details

### POST /batches (drain the sync queue)

Sends all pending `SyncQueueItem` rows as one Fineract batch request.

**Body** (`BatchSyncRequest`)

| Field | Type | Description |
|---|---|---|
| requests | array | Batched sub-requests |
| requests[].requestId | Int | Correlates with the response |
| requests[].relativeUrl | String | Target Fineract endpoint |
| requests[].method | String | HTTP method of the sub-request |
| requests[].body | String (JSON) | Sub-request payload |

**Response** (`BatchSyncResponse` — array)

| Field | Type | Description |
|---|---|---|
| requestId | Int | Matches the request |
| statusCode | Int | Per-sub-request status |
| body | String | Per-sub-request response body |

The response advances each queued row pending → in_progress → synced/failed via the Store5
Bookkeeper; conflicts surface for manual review.
