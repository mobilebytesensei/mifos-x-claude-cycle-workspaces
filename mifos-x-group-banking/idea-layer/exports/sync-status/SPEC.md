## Overview

Offline sync dashboard showing the current synchronisation state for the signed-in user across all
their group memberships (FR-008). On load it reads exclusively from the local SQLDelight
`sync_queue` table via a Flow — no network call — computing an overall status
(SYNCED / PENDING / FAILED), pending and failed counts, a per-`EntityType` breakdown, the last
successful sync timestamp, and a conflict count. A Sync Now button drains the queue on demand:
pending `SyncQueueItem` rows are batched into one Fineract `POST /batches` request and the response
advances each row pending → in_progress → synced/failed via a Store5 `MutableStore` + `Bookkeeper`;
conflicts surface for review. Online reachability comes from `cmp-network-monitor` — Sync Now is
disabled offline. Failed operations list per-item retry. This is a terminal read/action screen with
no outbound navigation. Localized (en/sw/fr/hi).

**Acceptance Criteria:**

- AC1: On mount, observe `sync_queue` (SQLDelight Flow), network state, and last-sync timestamp — no
       network read.
- AC2: `overallStatus` = SYNCED (pending==0 && failed==0) / PENDING (pending>0) / FAILED (failed>0),
       driving the status card color (green / amber / red) and icon.
- AC3: Pending breakdown card shows a count badge per `EntityType` (shown only when `pendingCount>0`).
- AC4: Conflict chip is shown only when `conflictCount > 0`.
- AC5: Sync Now is enabled only when `isOnline && !isSyncing`; it `POST /batches`, updates status from
       the result, and stamps last-sync. Offline shows the "Offline — Connect to sync" label / snackbar.
- AC6: Failed-operations card (only when `failedCount>0`) lists each failed item with its error and a
       per-item Retry that re-submits that one item; success moves it failed → synced.
- AC7: When `pendingCount==0 && failedCount==0`, the "All caught up!" empty state is shown.
- AC8: Pull-to-refresh re-reads the local DB.

## Flow Logic

| Decision | Condition | Path |
|---|---|---|
| `on_load` | mount | observe `sync_queue` (compute counts + overallStatus) + observe network + read last_synced_at |
| `on_sync_now` | guard `isOnline` (else snackbar "Offline — Connect to sync") | `batch_sync` → success: update status + last-sync · error: snackbar error_sync_failed |
| `on_retry_operation` | tap retry | `batch_sync` single item → success: mark synced · error: snackbar "remains in failed queue" |
| `on_refresh` | pull-to-refresh | re-observe `sync_queue` |

overallStatus rule: `SYNCED` if pending==0 && failed==0; `PENDING` if pending>0; `FAILED` if failed>0.
