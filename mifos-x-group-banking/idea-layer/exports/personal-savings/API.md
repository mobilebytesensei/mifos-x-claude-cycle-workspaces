## Offline Behaviour

The `savings_transactions` SQLDelight table serves cached rows (300 s stale-while-revalidate via
Store5) when `cmp-network-monitor` reports offline; a retry falls back to the last cached rows
instead of erroring. Pull-to-refresh invalidates the cache and forces a fresh fetch of both accounts.

## Error Type Map

| Error | Behaviour |
|---|---|
| `network.offline` | Serve cached transactions from SQLDelight (retryable) |
| `401 Session expired` | `Unauthorized` → session-expired handling |
| `404 Account not found` | Error state (account missing) |
| `503 Server unavailable` | `Server` → error state + retry |
