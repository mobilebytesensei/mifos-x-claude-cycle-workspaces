## Overview

Dual savings detail screen for members (member role, per-group). It reads the signed-in member's
own group-linked (mandatory, per-meeting contribution) and individual (voluntary) savings
transactions from Fineract `GET /self/savingsaccounts/{savingsId}/transactions`, cache-first via
Store5 + SQLDelight with a 300 s stale-while-revalidate window and `cmp-network-monitor` offline
fallback. Two chips switch between the Group-linked and Individual accounts (Individual chip is
hidden when `individualSavingsId == null`); switching lazily fetches the individual account the
first time it is selected. Each tab renders a balance hero card, a contribution-progress card
(group-linked only), and a color-coded deposit/withdrawal transaction history with running
balances. No money moves are initiated here — this is a read-only screen. Covers FR-017.

**Acceptance Criteria:**

- AC1: On mount fetch group-linked transactions (and individual transactions when
       `individualSavingsId != null`) in parallel; success → Content, error → Error.
- AC2: Reads are cache-first (Store5 + SQLDelight, 300 s SWR); fresh cache is served without a
       network call; offline falls back to cached rows.
- AC3: Tab switch is a pure state transition rebinding balance + transactions; individual tab
       lazily fetches on first selection.
- AC4: Individual chip is visible only when `individualSavingsId != null`; selecting Individual
       with no account shows the "No individual savings yet" promo.
- AC5: Contribution-progress card (group-linked only) shows `meetingsAttended / totalMeetings`
       with a progress bar.
- AC6: Transaction rows are color-coded — deposit (primary, `+`), withdrawal (error, `-`) — with a
       running balance; NO deposit/withdraw/transfer actions (read-only).
- AC7: Pull-to-refresh invalidates cache and re-fetches both accounts; 401 → Unauthorized.

  label, the balance in displaySmall bold, and the account number. Group-linked adds a contribution

  secondaryContainer promo card.
