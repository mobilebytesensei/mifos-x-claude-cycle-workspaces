## Overview

Confirmation dialog overlaid on the Settings screen when the user taps Logout. It asks for
confirmation before ending the session. On confirm it attempts to flush any queued offline
operations from the Store5 / SQLDelight `SyncQueueRepository`, then clears the local session via
`SessionManager` and deletes cached auth tokens from the `multiplatform-settings` DataStore, and
navigates to `login-signup`. If unsynced entries remain (or the flush fails), the user is warned
that some data may be lost — but the session is still cleared. There is NO Fineract API call —
`POST /authentication/logout` does not exist in Fineract, so logout is client-side only. Cancel /
outside-tap simply dismisses the dialog with no state change. Fully localized (en/sw/fr/hi).

**Acceptance Criteria:**

- AC1: Dialog opens with body text warning that unsynced changes may be lost; when the sync queue
       has pending ops, the count is surfaced.
- AC2: Confirm sets `isLoggingOut=true`, flushes pending ops (when online), clears the session, and
       emits `NavigateToLogin`.
- AC3: When offline, the flush is skipped and the session is still cleared (data may be lost).
- AC4: A flush error still clears the session but surfaces a "some data may not be synced" message.
- AC5: Cancel / outside-tap emits `Dismiss` — session intact, no API calls, returns to Settings.
- AC6: While `isLoggingOut`, the Log Out button shows a spinner and Cancel is disabled.

## API Endpoints (0)

None. Logout is a **client-side local action** — clears session/tokens from local storage. Fineract
has no logout endpoint (`POST /authentication/logout` does not exist).

## Flow Logic

| Decision | Condition | Path |
|---|---|---|
| `on_confirm_logout` | confirm | `isLoggingOut=true` → clear session from DataStore → success: navigate `login-signup` · failure: set `logoutError`, `isLoggingOut=false` |
| `on_dismiss` | cancel / outside | emit `Dismiss`, no state change |

Enriched behavior: before clearing, flush pending ops from `SyncQueueRepository` when online; skip
flush when offline; a flush error still clears the session with a "data may not be synced" message.
