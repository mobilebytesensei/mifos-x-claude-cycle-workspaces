## Overview

Unified authentication entry-point for the MifosSave companion app. A single
tab-toggle screen handles both returning-user login (COMP-AUTH-002) and new-user
self-registration (COMP-AUTH-001), plus biometric re-auth (COMP-AUTH-003) for
returning users. On SIGNUP the companion self-registration bridge atomically creates a
companion user plus a linked Fineract client and returns a session token with an empty
group list, routing to the `ZeroGroups` onboarding state. On LOGIN the returned
`groupMemberships` list drives routing: a non-empty list routes to
`personal-dashboard`/`group-list`, an empty list routes to `ZeroGroups`. The identifier
field is shared across both forms but validation is **mode-dependent** — LOGIN accepts an
email, an E.164 phone, OR a username (3–30 chars); SIGNUP still requires an email or
E.164 phone. Covers FR-013 (authentication), FR-014 (self-registration), and FR-021
(biometric offline re-auth).

**Acceptance Criteria:**

- AC1: Toggling `mode_toggle_tabs` between Sign In and Sign Up (`OnModeToggle`) swaps the
       visible form field set without navigation, resetting fields + clearing errors.
- AC2: `OnLoginTap` calls `companion_login` (COMP-AUTH-002); `OnSignupTap` calls
       `companion_self_register` (COMP-AUTH-001) — both via `core/network` + `core/session`.
- AC3: After auth success the returned `groupMemberships` determines routing — non-empty →
       `personal-dashboard`/`group-list`, empty → `ZeroGroups` state.
- AC4: Biometric unlock (`OnBiometricUnlock`) invokes `core/biometric`, then calls
       `companion_me` (COMP-AUTH-003) on success to refresh the profile + group memberships.
- AC5: `ZeroGroups` state renders `create_group_button` → `group-type-picker` and
       `join_with_code_button` → `join-with-code`.
- AC6: The identifier field validation is mode-dependent — LOGIN accepts email / E.164
       phone / username (→ `error_identifier_invalid`); SIGNUP requires email / E.164 phone
       (→ `error_email_phone_invalid`); its label/placeholder/keyboard also switch by mode.
- AC7: `SessionStore` (`core/session`) persists `sessionToken` encrypted in local
       preferences; auth requires connectivity — no offline auth fallback.

## Flow Logic

| Decision | Condition | Path |
|---|---|---|
| `on_load` | biometric available + stored valid session | set `isBiometricAvailable=true`; emit `PromptBiometric` (else show login form) |
| `on_login` | valid login form | `companion_login` → store session → inspect `groupMemberships` (non-empty → `NavigateToPersonalDashboard`, empty → `ZeroGroups`); error → set `error` |
| `on_signup` | valid signup form | `companion_self_register` → store session → always `ZeroGroups` (empty memberships); 409 → `error_account_exists` |
| `on_biometric_unlock` | prompt success | `companion_me` → refresh session → inspect memberships (non-empty → dashboard, empty → `ZeroGroups`); failure → `LoginSignupError.BiometricFailed` |
| `on_create_group_tap` | ZeroGroups | emit `NavigateToGroupTypePicker` |
| `on_join_with_code_tap` | ZeroGroups | emit `NavigateToJoinWithCode` |
| `on_forgot_password` | login | emit `ShowSnackbar` (web-portal / organizer reset guidance) |

**Validation rules:** `name` (min 2, max 80, required, signup) · `emailPhone` (required;
LOGIN `email_phone_or_username`, SIGNUP `email_or_e164_phone`) · `password` (required, min
8, max 64).
