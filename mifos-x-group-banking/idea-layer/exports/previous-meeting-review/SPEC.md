## Overview

Read-only recap of the previous closed meeting (FR-019), surfaced either at the start of a new
meeting (`launched_from == "conduct"`) or when an organizer taps a completed meeting on the
calendar (`launched_from == "calendar"`). It loads a full review — summary metrics (total
collected, closing corpus, fines, loans disbursed), per-member attendance, savings breakdown,
loan activity, and an unresolved-items alert — from the SQLDelight `LocalMeetingDao` cache first
(stale-while-revalidate 300 s), then refreshes via `MeetingRepository`; `cmp-network-monitor` gates
the background refresh so the recap renders offline. Previous-meeting data is immutable after
closing, so there are no mutations. The Start Meeting CTA is shown only in the `conduct` launch
context and forwards to `meeting-conduct` for the next meeting.

**Acceptance Criteria:**

- AC1: On mount, render cached data immediately if present and revalidate in the background;
       otherwise show the loading skeleton and fetch from the API.
- AC2: Context banner + CTA depend on `launchedFrom`: `conduct` → "Reviewing before Meeting #N"
       banner + Start Meeting CTA; `calendar` → "Completed Meeting" banner, no CTA.
- AC3: Unresolved-items alert card is shown only when `unresolvedItems.isNotEmpty()`.
- AC4: Summary card shows total collected (headlineLarge), closing corpus, fines, loans disbursed.
- AC5: Attendance rows are color-coded by status (PRESENT=primary, LATE=warning, ABSENT=error) and
       show a fine line when `fineAmount > 0`; savings rows show group/individual/total; loan rows
       show repaid/outstanding and a disbursed chip when `amountDisbursed > 0`.
- AC6: Start Meeting CTA (conduct only) navigates to `meeting-conduct` with `nextMeetingId`,
       `nextMeetingNumber`, `groupId`.
- AC7: Load failure shows the Error state; back returns to the launch origin (conduct or calendar).
