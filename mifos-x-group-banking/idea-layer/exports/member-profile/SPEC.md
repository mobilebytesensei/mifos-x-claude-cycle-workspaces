## Overview

Detailed profile for a single group member. A Store5 read store fans out three parallel
Fineract-REST reads on mount — `get_client` (identity, join date, phone),
`get_client_accounts` (savings balance + weekly savings sparkline + active-loan arrears),
and `get_member_role` (chama role) — merging them into one `MemberProfileState`, cached in
SQLDelight `members` / `member_accounts` tables with a 300 s stale-while-revalidate
SourceOfTruth so the profile renders instantly offline. Attendance rate is computed locally
from `meetingsAttended / totalMeetings`. A Chairperson-only Edit Role bottom sheet performs a
Fineract-REST `PUT /datatables/dt_member_role/{clientId}` write, invalidating the Store cache
on success. `cmp-network-monitor` gates every write and drives the offline fallback banner.

**Acceptance Criteria:**

- AC1: On mount fire `get_client`, `get_client_accounts`, `get_member_role` in parallel;
       Content only when all three succeed, Error on any failure.
- AC2: Attendance rate = `meetingsAttended / totalMeetings`, computed locally; progress bar
       color-codes ≥0.80=tertiary, ≥0.60=secondary, <0.60=error.
- AC3: Role chip is color-coded per role; Edit Role button is visible only when
       `isCurrentUserChairperson`.
- AC4: Active-loan card is shown only when `accounts.activeLoan != null`; an arrears banner
       + error-colored border render when `inArrears`.
- AC5: Edit Role bottom sheet selects a role locally (no network), then Confirm calls
       `update_member_role` only when `selectedRole != null && selectedRole != currentRole`;
       on success updates role state + snackbar, on failure snackbar + clears `isUpdatingRole`.
- AC6: View Full History navigates to `member-savings-detail`; Back navigates to `member-list`.
- AC7: Offline serves cached profile with a "Showing cached profile" message; 404 → NotFound,
       401 → Auth redirect to login.

## API Endpoints (4)

| Function | Method | Endpoint | Params / Body | Response | Errors | Cache |
|---|---|---|---|---|---|---|
| `get_client` | GET | `/clients/{clientId}` | clientId(Long) | object{id, displayName, firstname, lastname, mobileNo, status, activationDate, officeId} | 401, 403, 404, 500 | 300 s SWR |
| `get_client_accounts` | GET | `/clients/{clientId}/accounts` | clientId(Long) | object{savingsAccounts[], loanAccounts[]} | 401, 403, 404, 500 | 120 s SWR |
| `get_member_role` | GET | `/datatables/dt_member_role/{clientId}` | clientId(Long) | array{role, groupId, assignedDate} | 401, 403, 404, 500 | 300 s SWR |
| `update_member_role` | PUT | `/datatables/dt_member_role/{clientId}` | clientId(Long) + body{role, groupId, assignedDate} | object{resourceId} | 400, 401, 403, 500 | — (write) |

## Flow Logic

| Decision | Condition | Path |
|---|---|---|
| `on_load` | mount | parallel `get_client` + `get_client_accounts` + `get_member_role` → all success: Content · any error: Error |
| `on_edit_role_tap` | `isCurrentUserChairperson` | show sheet, seed `selectedRole=currentRole` |
| `on_role_selected` | tap option | set `selectedRole = role` (no network) |
| `on_confirm_role_change` | `selectedRole != null && selectedRole != currentRole` | `update_member_role` → success: set role, close sheet, snackbar · error: snackbar |
| `on_dismiss_role_edit` | dismiss | `isEditingRole=false, selectedRole=null` |
| `on_view_savings` | tap | navigate `member-savings-detail(memberId, groupId)` |
| `on_back` | tap | navigate `member-list(groupId)` |

## Data-Flow

**Tables**

| Table | PK | Mutation | Strategy |
|---|---|---|---|
| `members` (SQLDelight) | id | upsert | stale-while-revalidate 300 s; offline show_cached |
| `member_accounts` (SQLDelight) | memberId | upsert | stale-while-revalidate 120 s; offline show_cached |

**Sync Queue:** role update (`update_member_role`) is an online-gated write; on success the
Store cache is invalidated. `cmp-network-monitor` blocks the write when offline.
