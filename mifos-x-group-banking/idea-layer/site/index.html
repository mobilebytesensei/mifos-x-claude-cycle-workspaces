Why MifosSave

Built the way real groups actually work

Millions organize into VSLA/ROSCA/SHG groups to pool savings, issue loans, and distribute profits — today on paper ledgers prone to error and fraud. MifosSave replaces the ledger, not the group.

📴

Offline-first

Full functionality with no internet — every action is captured locally and syncs to Fineract automatically when connectivity returns.

🤝

Meeting-centric

Mirrors the real flow: attendance → savings → loans → decisions → close. The app follows the meeting, not a menu.

🏦

Fineract-backed

Enterprise-grade financial record-keeping via the proven open-source Mifos X / Apache Fineract core banking engine.

👁️

Transparent

Every member sees group balances, loan status, and live share-out projections in real time — no hidden ledger.

🔤

Low-literacy UX

Icon-heavy, minimal text, large touch targets, voice prompts — designed for field use by first-time smartphone users.

MifosSave API surfaces

Ten documented API areas power the app, layered over Mifos Fineract and orchestrated by the MifosSave companion backend. Each surface has a versioned spec in the idea-layer.

🔐 Authentication authentication.yaml

Self-register, login → groups + roles, and the current-user (me) resolver.

POST/self/registration
POST/authentication → groups+roles
GET/self/clients (me)

👥 Clients & members clients-members.yaml

Client (member) create, activate, and group association.

POST/clients
POST/clients/{id}?command=activate
GET/clients/{id}/accounts

🏘️ Groups & centers groups-centers.yaml

Group create/activate, staff + role assignment, center meetings.

POST/groups
POST/groups/{id}?command=activate
GET/centers/{id}/meetings

🗓️ Meetings meetings.yaml

Calendar, attendance, and collection-sheet submission per meeting.

GET/centers/{id}/collectionsheet
POST/centers/{id}/collectionsheet
POST/meetings/{id}?command=saveAttendance

💰 Savings savings.yaml

Group-linked savings accounts, deposits, and balances.

POST/savingsaccounts
POST/savingsaccounts/{id}/transactions?command=deposit
GET/savingsaccounts/{id}

💳 Loans loans.yaml

Apply, approve, disburse, list, and repay group loans.

GET/loans
POST/loans/{id}?command=disburse
POST/loans/{id}/transactions?command=repayment

🪙 Share-out share-out.yaml

Cycle share-out / rotation preview and execute.

GET/groups/{id}/shareout/preview
POST/groups/{id}/shareout/execute

🔄 Offline sync offline-sync.yaml

Sync metadata, delta pull, and queued-mutation push contracts.

GET/sync/delta?since=…
POST/sync/push (queued ops)

🙋 Self-service self-service.yaml

Member-facing self-service views over their own accounts.

GET/self/loans
GET/self/savingsaccounts

🧑‍💼 Field officer field-officer.yaml

Supervisory reads across an officer's assigned groups.

GET/staff/{id}/groups
GET/groups?officerId=…

The Mifos-X API behind it

Built on Mifos X / Apache Fineract

MifosSave is a client of the Mifos X platform — the open-source core banking engine used by financial institutions worldwide. Every balance, loan, and transaction is a real Fineract record.

1
Clients & groupsMembers are Fineract clients; savings groups are groups under a center, activated and staffed via the standard API.
2
Savings accountsGroup-linked savingsaccounts hold contributions; deposits post as real transactions with an auditable ledger.
3
LoansGroup loans flow through apply → approve → disburse → repay, each a Fineract command endpoint.
4
Meetings & collection sheetsThe collectionsheet API drives the meeting: attendance, savings, and repayments submitted together.
5
DatatablesVSLA/ROSCA-specific state (group type, rotations, auctions, cycles, welfare fund) lives in Fineract datatables, provisioned once on deploy.
6
Self-serviceThe /self/* API gives each member scoped read access to their own accounts — the basis for the end-user dashboard.
