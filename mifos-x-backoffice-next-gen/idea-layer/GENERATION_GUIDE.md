## Bootstrap Pipeline (`/idea sync` STATE A)

When idea-layer is missing or empty, `/idea sync` auto-detects the scenario and bootstraps
from ALL available data sources in one pass. No separate command needed.

| Phase | What It Does | Input Sources |
|-------|-------------|---------------|
| **PRE-SCAN** | Discover available data (source code + all layers) | source/*, idea-layer/exports/*, server-layer/*, client-layer/*, PROJECT.md |
| **PRE-POPULATE** | Build initial core files from discoveries | Discovery results |
| **DECOMPOSE** | Idea Decomposition Engine 5-pass | Pre-populated IDEA.md + FEATURES.md |
| **ENRICH** | Quality gate + full artifact generation | Decomposed content |

**Single source of truth**: `/idea sync` handles all scenarios automatically:
- Missing idea-layer (new project / first import) → bootstrap with source scan
- Stale idea-layer → re-enrich dirty flows
- Healthy idea-layer → verify + enrich as needed

**Command**: `.claude-runtime/commands/idea-sync.md` (STATE A Pre-Scan + Idea Decomposition Engine)

## `/dev` → option 2 (`/idea export`) — 3-Phase Resumable Pipeline

```
Phase 1: FLOWS     idea-layer/screens/{f}/ → idea-layer/flows/{flow_id}.yaml (T1) + idea-layer/screens/{f}/flow.yaml (T2) → idea-layer/APP_FLOW.mmd derived (Claude Intelligence)
Phase 2: FEATURES  flow.mmd + FR + screens → SPEC.md + API.md + STATUS.md (Claude Intelligence)
Phase 3: MOCKUPS   screens.json + design-tokens → MOCKUP.md + PROMPTS_STITCH + PROMPTS_FIGMA + FIGMA_LINKS (Claude Intelligence)
Phase 3.5: STITCH  PROMPTS_STITCH.md → prod/stitch/{screen}/code.html + screen.png (Stitch MCP, optional)
```

Each phase validates before proceeding. Per-feature state tracked in `GENERATION_STATE.yaml`.

| Run Scenario | Behavior |
|-------------|----------|
| First run | Generate all features × 3 phases |
| Nothing changed | "All up to date" (instant) |
| FR added | Only stale features regenerate |
| New feature added | Only new feature generates |
| `--force home` | Only home regenerates |
| `--force` | Regenerate everything |
| Stopped mid-run | Next run resumes from where stopped |

## Dashboard Shell

The prototype viewer (sidebar, toolbar, device switcher, inspector, flow/coverage tabs) is provided by the framework as a default dashboard shell:

| File | Location | Purpose |
|------|----------|---------|
| `APP_FLOW_DASHBOARD.html` | `templates/specialized/idea-layer/` | Default dashboard shell (framework-resident) |

**3 injection zones** in the shell:

| Zone | Variable | Replaced With |
|------|----------|---------------|
| 1 | `const APP_DATA = null;` | Serialized screens.json content |
| 2 | `const DESIGN_TOKENS = null;` | Serialized design-system/design-tokens.yaml (if exists) |
| 3 | `const PROJECT_META = {...};` | Project name, screen count, version |

**Generation + Self-Healing:**

| Step | What | How |
|------|------|-----|
| **Generate** | Shell + data injection | Read shell → inject APP_DATA/TOKENS/META → write app-flow.html |
| **Verify** | Render self-healing (STRICT) | Claude cross-checks every component type, icon, behavior, on_click against shell renderers |
| **Fix** | Auto-fix shell gaps | Claude reads shell source → adds missing renderers/icons/CSS → writes back → regenerates |
| **Custom** | User requests redesign | option (g): Claude generates entire HTML from scratch (ignores shell) |

**Dashboard features:** Sidebar (screen list, search, feature groups), Toolbar (platform switcher, device switcher, theme picker, tag toggle, inspector), Phone frame (375x812/768x1024/1280x800), Inspector panel, Flow diagram tab, Coverage tab, Toast/modal/sheet system, Keyboard shortcuts, 40+ SVG Lucide icons, M3 components, iOS Cupertino overrides.

**Self-Healing:** After every `/idea sync`, Claude verifies all component types in screens.json have working renderers in the shell. If a gap is found (missing renderer, broken CSS, unknown icon), Claude reads the shell source, fixes it, and writes the corrected shell back. The shell evolves — every project's sync improves it for ALL projects. This is a STRICT mandatory gate — /idea sync cannot complete without passing.

## screens.json Generation

| Generator | Quality | When Used | Components/Screen |
|-----------|---------|-----------|:-:|
| **Claude Intelligence** (ONLY) | Production | /idea sync, /project-add, /idea option 10, ALL generation | 8-12 |

**No script fallback.** Claude Intelligence is the ONLY generator. No Python, no Node, no bash.
If Claude cannot generate screens, the operation fails — never falls back to a lower-quality script.

**Production quality** means every screen passes 7 checks:
1. ≥6 components (trained baseline: 8-12 per screen)
2. Real list items (labels + subtitles, not descriptions)
3. Every button navigates
4. No placeholder text
5. Bottom-nav on main screens
6. Contextual headers
7. Proper component types (toggles, pickers)

### Trained Baselines (from mood-movies /idea train)

These baselines were learned from training the idea layer against 19 design features + 43 server migrations:

| Metric | Trained Value | Minimum |
|--------|:------------:|:-------:|
| Components per screen | 8-12 | 6 |
| States per screen | 4-6 (loading, error, empty, content, offline, partial) | 3 |
| FR per feature | 3-5 | 2 |
| SFR per feature | 4-8 | 2 |
| RPC functions per group | 8-22 | 3 |
| Columns per table (with enrichment) | 7-14 | 4 |
| Infra columns per table | 2-4 (created_at, updated_at, + soft delete/sync) | 2 |
| Indexes per table | 2-4 | 1 |
| RLS policies per table | 2-4 | 1 |

### Server Schema Enrichment (trained from production)

Every `tables/{domain}.json` MUST have column `source` tags (PLAN-fw-260329-006):
- `api`: API-facing columns (average 65% of columns)
- `infra`: created_at, updated_at, sync_status, deleted_at (average 18%)
- `computed`: Aggregations, scores, derived data (average 10%)
- `business`: Loyalty, premium, verification flags (average 4%)
- `denorm`: Denormalized title/name for join-free reads (average 3%)

### api_specs/ Generation (trained from production)

Every project with Supabase backend SHOULD have `api_specs/{group}.json` files:
- Group by domain (movies, users, moods, watchlist, analytics)
- Each function: name, params (with types + defaults), returns (TABLE definition), language, security, auth
- Typical distribution: 40-60% read (sql STABLE), 30-40% write (plpgsql VOLATILE), 5-10% admin (DEFINER)

**Claude generates + verifies in ONE PASS** per screen:
  READ context → GENERATE → VERIFY (7 checks) → WRITE only if passes

**Reads**: IDEA.md + FEATURES.md + REQUIREMENTS.md + PROJECT_CONFIG.yaml
**Writes**: screens.json → app-flow.html → TAG_REGISTRY.yaml

## Data Flow (CRITICAL — READ THIS)

### Direction: ALWAYS Downstream

```
idea-layer (YOU write) ──→ idea-layer/exports (Claude generates) ──→ source code
                        /idea export (ONE-WAY)

NEVER: idea-layer/exports → idea-layer (except one-time bootstrap)
```

### Bootstrap (One-Time Only)

When idea-layer is scaffolded for a project that already has idea-layer/exports:
1. `/idea` or `/project-migration add-idea-layer` detects empty idea + existing design
2. Reverse-engineers: SPEC.md → FEATURES.md, flows → screens.json, PROJECT.md → IDEA.md
3. Sets `bootstrapped: true` in LAYER_STATUS.md
4. From this point: idea-layer is the MASTER, design-layer is generated

### After Bootstrap

| Command | Reads | Writes |
|---------|-------|--------|
| `/idea` (options 1-5, 10) | idea-layer | idea-layer |
| `/dev` → option 2 (`/idea export`) | idea-layer | idea-layer/exports (generates) |
| `/design` | idea-layer/exports | idea-layer/exports (enhances detail) |
| `/implement` | idea-layer/exports | source code |

### What Gets Overwritten by `/dev` → option 2 (`/idea export`)

```
⚠️ /idea export OVERWRITES features/dev/ for stale/pending features:
  - idea-layer/exports/*/SPEC.md   ← overwritten (safe — dev only)
  - idea-layer/exports/*/API.md    ← overwritten (safe — dev only)
  - idea-layer/flows/{flow_id}.yaml (T1) + idea-layer/screens/{f}/flow.yaml (T2)
  - idea-layer/exports/FEATURES.md

✅ /idea export NEVER TOUCHES features/prod/ (human-promoted only)

Workflow:
  Edit idea-layer → /idea sync (Step G marks stale) → /idea export → /design promote
  Manual edits to features/dev/ WILL be lost on next /idea export.
  Manual edits to features/prod/ are SAFE (never auto-overwritten).
```

## Web Project Prototype Support

For `project.type: web` projects (Wix, React, Vue, etc.), the prototype system uses a **browser-frame renderer** instead of the phone-frame.

### Web vs Mobile Prototype

| Aspect | Mobile (KMP) | Web |
|--------|:------------:|:---:|
| Frame | Phone (375x812) | Browser (1280/768/375) |
| Component vocab | M3 mobile (34 types) | Web components (16 new + 8 shared) |
| Navigation | Bottom nav + back | Nav-bar + footer + breadcrumb |
| Entry point | Splash screen | Home page |
| States | loading, error, empty, auth, permission | loading (skeleton), error, empty (no results) |
| Viewport | Fixed phone | Switchable (Desktop/Tablet/Mobile) |

### Web Prototype Generation

During `/idea sync`, Claude:
1. Detects `project.type: web` from PROJECT_CONFIG.yaml
2. Converts section names to full web components
3. Generates nav-bar + footer on every page
4. Applies web quality checks (IDEA_LAYER_CHECKS.md)
5. Injects data into APP_FLOW_DASHBOARD.html (auto-detects web mode)
6. Dashboard renders with browser-frame + viewport switcher
