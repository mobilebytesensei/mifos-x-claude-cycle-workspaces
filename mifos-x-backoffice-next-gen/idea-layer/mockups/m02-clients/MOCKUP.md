## Screen Intent

The Clients module hub — an office-scoped searchable client list (`GET /v1/clients`, CACHE_FIRST_SWR) that drills into the **Client 360** (identity + permission-gated sub-resource tabs: Accounts / Identifiers / Documents / Addresses / Family / Charges / Notes) and a full **lifecycle command bar** (activate / close / reject / withdraw / propose-transfer / edit / add-identifier / upload-document / add-note). Every tab and command is resolved through `PermissionEvaluator` — denied is hidden, unmapped fails closed. Onboarding + lifecycle commands queue to the offline outbox. `requires_permission: [READ_CLIENT]`.

## Accessibility & Density Notes

- Lifecycle buttons are BOTH permission-gated and `enabled_when` status-matched — no invalid transition is offered.
- Destructive commands (Close / Reject / Withdraw) are `variant: destructive` with confirm.
- Status chips carry text + a queued-offline variant so the operator sees un-synced clients.
- 360 sub-resource tabs hidden (not greyed) when the read permission is absent — fail-closed.
