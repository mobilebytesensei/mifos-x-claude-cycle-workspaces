## Screen Intent

The product & charge configuration console: a tabbed catalog (Loan / Savings / FD / Share products · Charges · Funds · Tax · Floating rates · Delinquency buckets) with per-item detail and create/edit forms rendered from the entity template. Every create/edit/delete control is VISIBLE/enabled only per the user's `{ACTION}_{ENTITY}` permission. Config writes are deliberately **ONLINE-ONLY + maker-checker** (never deferred-sync — a GL-affecting config change must not replay silently later). Catalog rows drill into `product-editor`; rejected submissions surface in `needs-attention-inbox`.

## App Shell (resolved from `app-shell.yaml`)

- **Top app bar** — small M3, `surface`, title "Products & Charges", menu/back leading.
- **Bottom navigation** — visible as a module root. **FAB** — per-tab create FABs (loan/savings product, charge, fund, tax) gated on the matching CREATE_ permission.
- **Offline banner** — `config-online-only` state blocks writes with a "Connect to edit configuration" banner; catalog stays readable from cache.

Real content from `demo-data.yaml`: loan product **Group Business Loan** (short **GBL**) — working-capital loan for solidarity groups, **declining-balance** interest **2.0%/month (24% p.a.)**, principal **500,000** (min 50,000 / max 2,000,000), 12 repayments (6–24), Equal installments, fund **MFI Revolving Fund**. Each create/edit/delete control renders only for the matching permission; a read-only persona sees the catalog with no mutating controls.

### State: `template-loading` — catalog/template fetch
Catalog + (on create/edit) the `GET /{entity}/template` payload load CACHE_FIRST_SWR (large option lists: interest methods, repayment strategies, accounting rules, charge/GL options). Rows render as `shimmer-skeleton`.

### State: `empty` — no items in tab
A catalog tab has no items → illustration + empty message + a "Create {entity}" CTA (only with the matching CREATE_ permission).

### State: `submitting` — config posting online
A create/edit posts online to `POST /{entity}`; a maker-checkerable submission returns a commandId (empty changes) and lands "Submitted for approval" (PENDING_APPROVAL) — never optimistically applied.

### State: `config-online-only` — offline write blocked
An attempted config write while offline is BLOCKED with a "Connect to edit configuration" banner (`connect_to_edit_banner`); the catalog stays fully readable from cache underneath.

### State: `error` — fetch/submit failed
Server error verbatim (400 validation / 409 conflict) + Retry; a rejected maker-checker submission routes to `needs-attention-inbox`.

## Accessibility & Density Notes

- Config writes are ONLINE-ONLY + maker-checker — the offline block is explicit ("Connect to edit configuration"), never a silent deferred replay of a GL-affecting change.
- Delete is `effect: delete`, `variant: destructive` + confirm.
- Create controls hidden (not greyed) without the matching CREATE_ permission — fail closed.
- Rates/amounts in Roboto Mono for aligned config review.
