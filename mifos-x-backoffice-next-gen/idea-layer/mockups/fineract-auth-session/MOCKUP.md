## Screen Intent

The application entry gate. On cold start it first attempts to **restore** a persisted encrypted session (base-url, tenant, basic-token, userId, permission codes) — if present the app is already authenticated and routes straight to the capability bootstrap. Otherwise it shows the classic Fineract Basic-auth login: base-URL (server), tenant identifier (default "default"), username, password. On Sign in it `POST /authentication`, builds the Basic token, persists the session encrypted, populates the PermissionSet that `core/permissions` consumes, and flips the real `AuthProvider` to `isConfigured=true`. A **401 anywhere in the app drops the session back here**.

## App Shell (resolved from `app-shell.yaml`)

- **No app chrome** — this is the pre-auth gate: no bottom navigation, no drawer, no FAB. A centered branded login card on `background #FCFCFF`.
- **Top app bar** — minimal / branded header only ("Sign in").
- **Offline banner** — n/a pre-auth; connectivity errors surface as the inline `error_banner`.

### State: `restoring` — cold-start session read
Reading the persisted encrypted session from secure settings (no network). A centered progress indicator; a valid session routes straight to `permission-capability-engine`; absence / read failure falls through to `input`.

### State: `authenticating` — auth in flight
Sign in tapped — `POST /authentication` in flight. All fields + Sign in disabled with a progress indicator; nothing is persisted until success.

### State: `error` — auth failed
Invalid credentials (401), invalid/unreachable base-URL, network error, or a server-required next step (password change / 2FA) → inline `error_banner` above the form explaining the reason; fields re-enabled with entered values retained; `retry_button` re-submits (a 401 requires editing the fields first).

### State: `authenticated` — session established
Base-url, tenant, basic-token, userId and the permission code set are held by the real `AuthProvider` (`isConfigured=true`) and persisted encrypted; the screen routes forward to `permission-capability-engine` which builds the gated surface.

## Accessibility & Density Notes

- Sign in enabled only when base-URL is a valid http(s) URL and tenant/username/password are non-empty — no dead submit.
- Password field masked; raw password never persisted (only the base64 Basic token in encrypted settings).
- Error banner states the reason in words (invalid credentials / unreachable server / no network / 2FA required), not colour alone.
- `base_url_field` + `tenant_field` support any self-hosted Fineract deployment — the app is not tied to one server.
