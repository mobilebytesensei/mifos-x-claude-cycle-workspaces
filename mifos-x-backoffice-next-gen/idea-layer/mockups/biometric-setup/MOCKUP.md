## Screen Intent

First-time biometric enrollment screen — surfaces after passcode-lock setup or when the user toggles biometric lock in M17 Sync & Settings. Checks platform biometric availability (`BiometricManager.canAuthenticate`) on mount and routes to one of three states: `prompt` (AVAILABLE — show enrollment UI), `unavailable` (hardware not present), or `not_enrolled_in_os` (hardware present but no fingerprint/face enrolled in OS settings). On enroll, opens the native system biometric dialog; on success, persists `biometric_lock_enabled=true` + `biometric_type`. Biometric is a second factor that supplements passcode-lock, not a standalone lock — passcode must already be enabled. No Fineract API calls.

## App Shell (resolved from `app-shell.yaml`)

## Accessibility & Density Notes

- `illustration` carries `contentDescription "fingerprint sensor illustration"` / `"face ID illustration"` / `"setup success"` — meaningful, not decorative.
- `description_text` mentions the passcode fallback explicitly — users with accessibility needs can rely on PIN without feeling forced to use biometrics.
- `skip_button` is always reachable from `prompt` and `error` — biometric setup is optional, never blocking.
- The `not_enrolled_in_os` state's `open_os_settings_button` deep-links to the exact OS settings page (Android: `ACTION_BIOMETRIC_ENROLL`, iOS: `LocalAuthentication` enrollment guidance) — not the root settings.
- On return from OS settings, the screen re-checks availability automatically without requiring the user to navigate back and forward manually.
