## Screen Intent

The sectioned loan/savings product create & edit form, drilled into from the M08 Products & Charges catalog (`open_product_detail`) or the M08 "new product" affordance. Renders the product's configuration in five collapsible sections — Details · Terms · Settings · Charges · Accounting — merging `GET /v1/loanproducts/{productId}` with `GET /v1/loanproducts/template` so every field, bound and option matches the server's product schema. Each field is editable with template-driven options and per-field/section validation (`OnFieldChange` re-runs bounds checks and gates Save). Save persists a create (`POST /v1/loanproducts`) or update (`PUT /v1/loanproducts/{id}`) through the durable offline outbox with an idempotency key — **online-only**, per the M08 admin/config maker-checker contract. Product + template reads are CACHE_FIRST_SWR through Store5, so the form opens and stays browsable offline even though Save itself requires connectivity. Admin-only: gated on `CREATE_LOANPRODUCT` / `UPDATE_LOANPRODUCT`; without the permission the form renders fully read-only.

Two grounded error variants (`ui.yaml#state_model.errors` via `docs.yaml#error_cases`):
- **`product_load_failed`** — `GET /v1/loanproducts/4` failed with no `loan_product_cache` entry available (cold start / evicted cache).
- **`template_load_failed`** — `GET /v1/loanproducts/template` failed with no `loan_product_template_cache` available; without the template the form cannot render field options or validation rules at all.
- A hard **`save_failed`** (Save rejected with no fallback) reuses this same error surface with a save-specific message and Retry re-attempting the save instead of the initial load.

No shimmer, no form fields, and no Save button are shown in this state.

## Accessibility & Density Notes

- Collapsible sections keep a large product config navigable on a dense admin console; each section header carries an accessible label for screen-reader jumps between Details/Terms/Settings/Charges/Accounting.
- Save is **online-only + maker-checker** (per `data-flow.yaml`) — never a silently-deferred replay of a GL-affecting product change; an offline attempt shows the connect banner instead of queuing.
- Principal, interest-rate and repayment figures render in Roboto Mono (`font_family_mono`) so digits align during config review, matching the framework-wide numeric convention (`COMPONENTS.md` Do's & Don'ts).
- Read-only mode disables every `pe_field` (opacity 0.38) rather than hiding the form — the loaded terms stay visible for review even without edit rights; `pe_save` is fully absent (not merely disabled) when the user lacks both `CREATE_LOANPRODUCT` and `UPDATE_LOANPRODUCT`.
- Min/max bounds are shown inline next to each bounded field (e.g. "min 5,000 · max 100,000") so a validation failure is self-explanatory without a separate help panel.
