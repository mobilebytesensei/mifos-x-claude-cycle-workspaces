## Screen Intent

The capability bootstrap — resolves the signed-in user's PermissionSet + CapabilityMap after login (normalize `permissions[]`, compute the fingerprint, resolve umbrella short-circuits, build the gated 17-module roster). It surfaces the persona summary, umbrella flags, per-module visibility (N of 17 gated), checker-inbox availability, and the capability-map version. This is the keystone of the "same binary renders per permission" model — every module root is VISIBLE / DISABLED(reason) / HIDDEN per the resolution; unmapped ids fail closed.

## App Shell (resolved from `app-shell.yaml`)

- **No standard app chrome pre-surface** — this screen builds the surface. A branded header + persona card on `background`.
- **Top app bar** — minimal "Access & Permissions". **Offline banner** — the last-known encrypted set is retained so the surface stays usable offline.

### State: `loading` — resolving
Normalizing `permissions[]`, computing the fingerprint, resolving umbrella short-circuits, building the gated roster; a resolution shimmer.

### State: `unauthenticated` — no valid set
Login incomplete, `shouldRenewPassword` forces a password change, or 2FA required → routed back to `fineract-auth-session`; no surface built.

### State: `error` — capability map failed
Malformed permission payload, missing/checksum-invalid capability-map.json, or refresh-fetch failure → Retry rebuilds; the last-known encrypted set is retained so the app stays usable offline.

## Accessibility & Density Notes

- Umbrella short-circuit is stated as a text badge (ALL_FUNCTIONS / ALL_FUNCTIONS_READ) — the client never enumerates effective permissions for a super-user.
- Module roster visibility is three-valued (VISIBLE / DISABLED-with-reason / HIDDEN); unmapped ids fail closed.
- Fingerprint + map version in Roboto Mono so an operator can quote the exact resolution to support.
- The last-known encrypted set is retained — a capability-map failure never locks the operator out offline.
