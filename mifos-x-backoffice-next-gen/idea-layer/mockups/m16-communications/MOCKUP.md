## Screen Intent

The messaging admin, tabbed across **Campaigns** (SMS/email campaigns with triggers + recipient reports), **Templates** (the message template library), and **Hooks** (webhook registrations) plus the email/external-service config. Campaign lifecycle — create, edit, activate, close, view recipient report — is permission-gated; create/activate/close commands queue to the offline outbox (optimistic status, reconcile-on-sync); rejected commands surface in `needs-attention-inbox`.

## App Shell (resolved from `app-shell.yaml`)

- **Top app bar** — small M3, `surface`, title "Communications", menu/back leading.
- **Bottom navigation** — visible as a module root. **FAB** — `new_campaign_button` → `dynamic-template-forms` (CREATE_SMSCAMPAIGN).
- **Offline banner** — `offline_banner`: cached campaigns/templates/hooks + "N queued · will sync when online".

### State: `loading` — campaign/template shimmer
Header + tabs stay; campaign rows / template cards render as `shimmer-skeleton` (Store5 Loading).

### State: `empty` — no campaigns/templates/hooks
Empty state offers "New campaign" (CREATE_SMSCAMPAIGN) or "New template" (CREATE_TEMPLATE), else "No campaigns yet".

### State: `submitting` — campaign command queuing
A create/activate/close posts or writes to the outbox; the control spins with a "Queued" chip; status is optimistic and reconciles on sync.

### State: `no-network` — offline cached
Persistent offline banner with queued-command count; cached campaigns/templates/hooks served; captive-portal aware.

### State: `error` — fetch/command failed
Server error + Retry; `review_failed_button` routes rejected campaign commands to `needs-attention-inbox`.

## Accessibility & Density Notes

- Campaign lifecycle permission-gated; destructive Close confirms; rejected commands surface in `needs-attention-inbox`.
- Merge tokens (`{{client.displayName}}` …) shown in Roboto Mono so template variables are unambiguous.
- Status chips carry text + a queued-offline variant so operators see un-synced campaign states.
