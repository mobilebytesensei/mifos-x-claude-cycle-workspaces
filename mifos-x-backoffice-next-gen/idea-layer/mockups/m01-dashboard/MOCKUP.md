## Screen Intent

The canonical **"same binary renders per permission"** home surface. Every KPI card, quick-action tile, and activity row is resolved through `core/permissions`' `PermissionEvaluator`, so a tile is present ONLY if the signed-in user holds its gating permission. No role branching — a system admin sees every tile via the `ALL_FUNCTIONS` umbrella; a collections field officer sees today's route; an accountant sees pending journals; an auditor sees every read tile with **zero** mutating quick-actions. Each tile hydrates independently (`CACHE_FIRST_SWR`) so one failing tile shows an inline error placeholder and never blanks the rest.

Fineract sources: `GET /v1/runreports/{reportName}` (PAR / active-clients KPIs), `/v1/collectionsheet` (today's route), `/v1/makercheckers` (pending-approvals count), `/v1/notifications` (recent activity).

### State: `empty` — no permitted tiles

Centered `empty-state` (`surface`, `on-surface-variant`, `spacing.xl` padding): friendly "No dashboard tiles available for your access" with a **View my access** link (`link` → `permission-capability-engine`). Screen is never blank. Sourced from `dash_no_access` persona (`tile_count: 0`).

### State: `partial-tile-error` — one tile failed, rest intact

Content grid renders normally; the failing card swaps to an inline error block — `status-chip-error` (`error-container #FFDAD6`) with a headline "Couldn't load" and a per-tile `[ Retry ]` `button` (`retry_tile_button`, `retry_failed_tile` → `call_api` ktorfit, reads `dashboard_tile_cache`). Every other permitted tile keeps its live/cached value. One failing tile never blanks the rest.

### State: `no-network` — offline, cached values

Persistent `offline-banner` (`#B45309`) across top. Every permitted tile shows its last cached value; tiles never cached show a "not synced yet" hint. Tapping a tile still navigates (targets read from cache). Demo: collections-officer "Repayment KES 3,000 queued (offline)".

### State: `error` — roster unresolvable

Full-screen retry: `[!]` error icon + "Couldn't load your dashboard" + `[ Retry ]` (`retry_dashboard_button`, `retry_dashboard` → `transform_state` multiplatform-settings, reads `retained_permission_set`). The last-known encrypted PermissionSet is retained so the app stays usable; only an absent retained set routes to re-authenticate.

## Accessibility & Density Notes

- Every interactive card ≥ 48dp touch target; `retry_tile_button` / `retry_dashboard_button` carry `accessibility_label` (`{strings.m01_retry_tile_a11y}` / `{strings.m01_retry_dashboard_a11y}`).
- Text scales to 200% without layout break; KPI values use Roboto Mono so digits stay column-aligned.
- Per-tile failure isolation is an a11y win — screen-reader focus stays on working tiles; only the failed card announces its error + Retry.
- WCAG AA: every fill/text pair in the token set is ≥ 4.5:1 (white on `#006CB5`, `on-surface` on `surface`).
