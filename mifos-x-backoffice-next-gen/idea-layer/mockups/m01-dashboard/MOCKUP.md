## Screen Intent

The canonical **"same binary renders per permission"** home surface. Every KPI card, quick-action tile, and activity row is resolved through `core/permissions`' `PermissionEvaluator`, so a tile is present ONLY if the signed-in user holds its gating permission. No role branching — a system admin sees every tile via the `ALL_FUNCTIONS` umbrella; a collections field officer sees today's route; an accountant sees pending journals; an auditor sees every read tile with **zero** mutating quick-actions. Each tile hydrates independently (`CACHE_FIRST_SWR`) so one failing tile shows an inline error placeholder and never blanks the rest.

Fineract sources: `GET /v1/runreports/{reportName}` (PAR / active-clients KPIs), `/v1/collectionsheet` (today's route), `/v1/makercheckers` (pending-approvals count), `/v1/notifications` (recent activity).

### State: `no-network` — offline, cached values

Persistent `offline-banner` (`warning-strong #B45309` fill, white text) across top. Every permitted tile shows its last cached value; tiles never cached show a "not synced yet" hint. Tapping a tile still navigates (targets read from cache). Demo: `dash_collections_officer` recent-activity shows "Repayment KES 3,000 queued (offline) · just now".

### State: `error` — roster unresolvable

Full-screen retry: `[!]` error icon (`error #BA1A1A`) + "Couldn't load your dashboard" + `[ Retry ]` (`retry_dashboard_button`, `retry_dashboard` → `transform_state` multiplatform-settings, reads `retained_permission_set`). ## Accessibility & Density Notes

- Every interactive card ≥ 48dp touch target (`touch_targets.comfortable`); `retry_tile_button` / `retry_dashboard_button` carry `accessibility_label` (`{strings.m01_retry_tile_a11y}` / `{strings.m01_retry_dashboard_a11y}`).
- Text scales to 200% without layout break; KPI values use Roboto Mono so digits stay column-aligned.
- Per-tile failure isolation is an a11y win — screen-reader focus stays on working tiles; only the failed card announces its error + Retry.
- **WCAG contrast caveat (per `design-tokens.yaml` metadata note)**: `on_primary` white text on a raw `primary #0091EA` fill is ~2.6:1 — below the WCAG-AA 4.5:1 body-text threshold. This mockup therefore reserves flat `primary` fills for large/bold labels and icons only (e.g. active-nav glyphs); any AA-critical text-on-primary surface (the selected bottom-nav pill) uses `primary_container #CBE6FF` / `on_primary_container #001E30` (7:1+) instead. Every other fill/text pairing used above (`on_surface` on `surface`, `on_error_container` on `error_container`, white on `warning_strong`) is ≥ 4.5:1.
