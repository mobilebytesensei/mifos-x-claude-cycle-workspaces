## Screen Intent

Read-only diagnostic drilled into from the permission-capability-engine (`view_capability_map_meta`). Shows the active **CapabilityMap** metadata — version, sha256 checksum, minAppVersion, source (bundled asset vs remote) — over a per-module **requirement tree**: one node per back-office module (M01…M17 + foundation features), each annotated with the permission group it requires and a **satisfied/denied** badge computed against the signed-in user's resolved PermissionSet. This is how an operator answers "why did my surface resolve the way it did?" Renders fully offline from the bundled/cached map. Any authenticated user may inspect it (`requires_permission: []`).

## Accessibility & Density Notes

- `cm_module` a11y label describes expand-to-reveal-codes; `cm_copy_checksum` announces "Copy the capability map sha256 checksum to the clipboard".
- Satisfied/denied is never colour-only — the ✔ / ⊘ glyph + chip text carry the state for colour-blind operators.
- Checksum is selectable/copyable; Roboto Mono keeps the 64-char hash legible.
