## Screen Intent

The self-scoped maker-checker approvals queue (M15), drilled into from the M01 dashboard "checker inbox" tile. Loads `GET /v1/makercheckers` (self-scoped to entries the user `canCheck(action,entity)` or `CHECKER_SUPER_USER`) into a filterable list — filter chips by **entity** (Loan · Client · Savings · GL) and by **action** (create/approve/disburse). Each row shows the queued command's action, entity, maker, made-on date and a command summary. Inline **Approve / Reject** post `POST /v1/makercheckers/{auditId}?command=approve|reject`; all decisions route through the offline outbox with a durable idempotency key. Rows the user cannot check render read-only.

## App Shell (resolved from `app-shell.yaml`)

- **Bottom navigation** — suppressed on this drilled-in queue.

## Accessibility & Density Notes

- Reject is `variant: destructive` and requires an explicit confirm — never a single-tap irreversible action.
- Approve/Reject a11y labels name the target entry; the resolving-row spinner announces progress.
- Amounts + account numbers in Roboto Mono for column-aligned scanning across the queue.
- Offline decisions are never dropped — a queued Approve/Reject shows an outbox badge until sync.
