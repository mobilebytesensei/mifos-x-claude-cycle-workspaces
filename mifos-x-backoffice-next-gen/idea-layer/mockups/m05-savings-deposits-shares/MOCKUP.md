## Screen Intent

The deposit-accounts module: a scope-filtered account list across **Savings · Fixed/Recurring Deposits · Shares**, drilling into an account detail with the full servicing surface — open/edit/approve/activate, deposit/withdrawal, hold/release amount, post interest, premature-close (FD), subscribe/redeem shares, account transfer, standing instruction, close. Every control is permission- and status-gated; monetary commands route through the offline outbox exactly-once; rejected commands surface in `needs-attention-inbox`. `requires_permission` READ on the deposit entities.

## App Shell (resolved from `app-shell.yaml`)

- **Top app bar** — small M3, `surface`, title "Savings & Deposits", menu/back leading.
- **Bottom navigation** — visible as a module root. **FAB** — `open_account_button` Teal → `dynamic-template-forms` (CREATE_SAVINGSACCOUNT).
- **Offline banner** — `no-network` shows cached account data (captive-portal aware); commands queue.

### State: `loading` — list/detail shimmer
Header + type tabs stay; account rows / detail render as `shimmer-skeleton` (Store5 Loading).

### State: `empty` — no accounts
No accounts in scope; empty state offers "Open an account" (CREATE_SAVINGSACCOUNT).

### State: `submitting` — command posting/queuing
A servicing command (deposit / withdrawal / interest / transfer) is posting online or writing to the durable outbox; spinner + disabled controls prevent double-tap.

### State: `error` — fetch/command failed
Server error + Retry; `review_failed_button` routes rejected commands to `needs-attention-inbox`.

### State: `no-network` — offline cached
Cached reads served with an offline banner; captures still queue.

## Accessibility & Density Notes

- Servicing actions permission+status gated; destructive (close/premature-close) confirm + maker-checker aware.
- Monetary figures + interest rates in Roboto Mono for aligned scanning.
- Offline captures queue exactly-once; rejected commands are surfaced, never dropped.
- Status chips carry text, never colour alone.
