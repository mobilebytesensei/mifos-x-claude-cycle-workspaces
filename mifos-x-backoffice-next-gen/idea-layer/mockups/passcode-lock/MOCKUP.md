## Screen Intent

Device-local PIN app-lock — shown on cold start (when `passcode_enabled=true`) and after 15 seconds in the background. Full-screen surface with no top app bar and no bottom navigation: the PIN lock replaces the full chrome. Two modes: **SETUP** (first use — entered from M17 settings biometric/passcode toggle) where the user sets a 6-digit PIN and confirms it; **LOCKED** (re-lock after background timeout) where the user enters their PIN or uses the platform biometric prompt. PIN is bcrypt-hashed before persistence — never stored in plaintext. After 5 consecutive wrong PINs, the pad is disabled with an exponential backoff countdown (30s → 2min → 10min). No Fineract API calls — entirely local `multiplatform_settings_encrypted`.

### State: `confirm` — PIN confirmation step (Carlos López)

Header changes to `"Confirm your passcode"`. Fresh empty dot row (new 6-entry). User re-enters the PIN. On match: hash persisted, `passcode_enabled=true`, routes to app shell. On mismatch: `error` state (shake animation → auto-reset to `setup` after 1.5s).

### State: `locked_biometric` — platform BiometricPrompt active

In-app screen shows the same `locked` layout (header + user info + dot row + keypad) with the `biometric_button` highlighted. The OS system biometric dialog is displayed on top (Android/iOS platform UI). User may dismiss the dialog to fall back to PIN. On biometric success: `UnlockSuccess` event emitted → app shell assembled state.

### State: `locked_out` — 5 consecutive wrong PINs (first tier: 30s)

```
┌──────────────────────────────────────────────────┐
│                                                  │
│          Enter your passcode                     │
│             Ana García · Oficina Central         │

│                                                  │
│   ┌──────────────────────────────────────────┐   │
│   │  ⏱  Try again in 1 min 42 sec            │   │  lockout_countdown chip (teal outline)
│   └──────────────────────────────────────────┘   │
│                                                  │
│      [digit pad — grayed out, non-interactive]   │
│                                                  │
└──────────────────────────────────────────────────┘
```

`lockout_countdown` chip decrements every second (CountDownTimer coroutine). When it reaches zero, state transitions back to `locked` and the pad re-enables (`failed_attempts` reset). Exponential tiers: 30s (5 fails) → 2min (6 fails) → 10min (7+ fails). Max lockouts → session cleared → route to login.

### State: `error` — wrong PIN or PIN mismatch

Dot row performs a **shake animation** (horizontal oscillation, ~300ms). Dots immediately reset to empty. `error_label` appears below the dots:
- Locked mode: `"Incorrect PIN · 3 attempts remaining"` (2 failed, 3 remaining before lockout)
- Setup/confirm mode: `"PINs don't match — please try again"`

After 1.5s the state auto-resets: locked mode → `locked` (with incremented `failed_attempts`); setup/confirm → `setup` (both entries cleared).

## Accessibility & Density Notes

- Full-screen lock: no back navigation or swipe-dismiss — the lock is enforced.
- `digit_pad` keys carry `contentDescription "Digit {n}"` for screen readers.
- `biometric_button` accessibility_label: "Unlock with biometric authentication".
- Shake animation uses `AccessibilityManager.isEnabled` to respect reduced-motion preferences — falls back to a color pulse if reduced-motion is on.
- `lockout_countdown` announces remaining time to screen readers via `LiveRegion.POLITE` once per 10s decrement.
- PIN dots are `contentDescription "N of 6 digits entered"` — screen reader gives feedback without echoing the digit value.
