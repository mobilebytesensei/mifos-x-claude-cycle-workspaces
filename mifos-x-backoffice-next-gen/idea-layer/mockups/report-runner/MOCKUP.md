## Screen Intent

The parameterised report run + result surface, drilled into from the M14 Reports catalog and the M01 dashboard PAR tile. Resolves the report's parameter metadata + lookup options into a dynamic parameter form, runs the report via `GET /v1/runreports/{reportName}` on Run, and renders the result as a sortable table (or chart for a Chart-type report), with a CSV/PDF export to the platform share sheet. Read-only; gated on `READ_REPORT` / the report's own `READ_{reportName}`.

- **Top app bar** — small M3, `surface`, title = report name, back leading (drill-in from M14 / dashboard).
- **Bottom navigation** — suppressed on this detail. **FAB** — none. **Offline banner** — a cached same-parameter result resolves offline (`report_result_cache`).

### State: `empty` — zero rows

The report ran successfully but returned zero rows for the chosen parameters (`demo-data.yaml#empty_state`: "No rows returned for the selected parameters") → no-data panel with adjust-parameters guidance. Parameter form remains visible above the panel so the operator can adjust and re-run.

### State: `error` — resolve/run failed

Parameter metadata failed to resolve (`parameters_load_failed`), or the run failed hard with no cache (`report_run_failed`) → centered error block + `[ Retry ]` (`rr_error_retry` → `call_api`, re-resolves parameters or re-runs).

## Accessibility & Density Notes

- Read-only surface; Run gated on `READ_REPORT` / the report's own read permission — hidden/disabled without it.
- Result numerics rendered in Roboto Mono so columns align; sort direction shown by a header glyph, never colour alone.
- Export hands off to the platform share sheet (CSV/PDF) — no in-app file handling.
- Empty (zero-row) result is distinguished from an error state, with adjust-parameters guidance rather than a hard failure message.
- All monetary values are formatted in **KES** (Kenyan Shilling) — never `$`/USD.
