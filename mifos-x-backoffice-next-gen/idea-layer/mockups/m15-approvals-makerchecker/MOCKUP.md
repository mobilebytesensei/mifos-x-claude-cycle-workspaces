## Screen Intent

The full maker-checker approvals module — the dedicated four-eye checker queue and the WRITE/action counterpart to needs-attention-inbox. Loads the self-scoped queue (`GET /v1/makercheckers`), **grouped** under entity/action/maker headers with per-group counts. Each row opens a payload inspect panel; **Approve / Reject / Delete** render only when the checker `canCheck(entry.action, entry.entity)` (CHECKER_SUPER_USER or `{ACTION}_{ENTITY}_CHECKER`) — no role branching, purely permission resolution. A multi-select bar enables **bulk-approve** across an already-canCheck-gated selection. Every decision enqueues to the offline outbox with a durable idempotency key and replays EXACTLY-ONCE via `POST /v1/batches`; a resolving row is locked from re-selection so a command can never be double-approved.

## Accessibility & Density Notes

- Approve / Reject / Delete render only on rows where the checker `canCheck(entry.action, entry.entity)` — CHECKER_SUPER_USER or the entry's `{ACTION}_{ENTITY}_CHECKER`; otherwise hidden, never disabled-with-a-tooltip.
- Reject and Delete are destructive; Delete requires an explicit confirm dialog before enqueue.
- A resolving row is locked from re-selection while `status IN (pending, retrying)` — a command can never be double-approved.
- Bulk-approve only ever operates over entries already canCheck-gated at selection time; the checkbox itself is absent on unauthorized rows.
- The `open_needs_attention_link` cross-link is strictly read-only — M15 never mutates the needs-attention-inbox feed.
- Minimum touch target 48dp on all interactive rows/buttons per `touch_targets.comfortable`; supports system font scaling 85%–200%.
- Loading-state shimmer mirrors the content-state grouped layout block-for-block (same row heights, same group-header positions).
