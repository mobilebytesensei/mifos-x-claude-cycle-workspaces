## Screen Intent

Single-loan drill-in from the M01 dashboard "quick take repayment" tile, the M04 loan-portfolio list, and the needs-attention-inbox. Loads `GET /v1/loans/{loanId}?associations=all` (summary, repayment schedule, transactions) cache-first through Store5 into a **summary header + tabbed body (Schedule · Transactions · Details)** with a permission-gated lifecycle action bar. Each action is evaluated against the PermissionSet **and** the loan status (Approve only on pending-approval, Disburse only on approved, Make repayment only on active). Mutations route through the offline outbox (`draft_outbox`) with a durable idempotency key, replayed exactly-once via `POST /v1/batches`. `requires_permission: [READ_LOAN]`.

## Accessibility & Density Notes

- Action bar buttons are status+permission gated; the domain use case re-checks `canDo` before dispatch/replay — a hidden button is never merely disabled-and-clickable.
- The Active status-chip and the overdue-period indicator carry text ("Active", "Overdue"), not colour alone, per WCAG 1.4.1.
- Schedule and ledger figures render in `font_family_mono` for column-aligned reading of the amortised table and transaction amounts.
- Minimum touch target 48dp on `ld_repayment` / `ld_approve` / `ld_disburse` / `ld_error_retry` per `touch_targets.comfortable`.
- `ld_client_link` carries `accessibility_label: "Open the borrower's client 360 profile"`; `ld_error_retry` carries `accessibility_label: "Retry loading the loan detail"`.
