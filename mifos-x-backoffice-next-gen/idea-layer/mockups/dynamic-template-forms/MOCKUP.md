## Screen Intent

The foundation form engine: renders a create/edit form for **any** Fineract entity purely from the server-returned `GET /{entity}/template` payload (field defaults + allowed-value option lists) joined with the entity's registered `GET /v1/datatables` schemas. **No field is hardcoded** — a back-office config change (new datatable column, new code value) surfaces on the next sync with zero app release. Submits assemble a `JsonObject` command body and flow through the offline outbox so forms stay fully usable with no connectivity. Consumed by client-create (from `client-list` FAB), loan mutations, and every state-transition command form.

## App Shell (resolved from `app-shell.yaml`)

- **Top app bar** — small M3, `surface`, title = the entity/command being captured (e.g. "New Client"), back leading.
- **Bottom navigation** — suppressed on this modal form flow.
- **FAB** — none; the primary action is the fixed **Submit** button. **Offline banner** — `queued-offline` state renders a banner explaining the command was enqueued to the outbox.

### State: `template-loading` — schema fetch
`GET /{entity}/template` + `GET /v1/datatables` in flight (CACHE_FIRST_SWR — serves cached schema instantly, revalidates in background). Field rows render as `shimmer-skeleton`.

### State: `validation-error` — inline field errors
One or more fields failed client validation (mandatory-missing, length/regex, date-format/range, allowed-value) → offending fields highlighted with `text-field-error` (error-tinted text/helper); Submit blocked until resolved.

### State: `submitting` — posting online
Assembled `JsonObject` posting to `POST /{entity}?command={action}`; fields + Submit disabled with a progress indicator.

### State: `queued-offline` — enqueued to outbox
No connectivity (or a per-domain offline-queued entity) → an `offline-banner`: "Saved offline — will submit on next sync". The command payload sits in the DraftEntity outbox with a durable idempotency key for exactly-once batch replay.

### State: `error` — fetch/submit failed
Template fetch failed with no cached schema, or the server rejected with 400 validation / 409 conflict → error message + `[ Retry ]` (`retry-button` → re-fetch template).

## Accessibility & Density Notes

- Mandatory fields marked with `*` and an a11y "required" state; validation errors announced inline, not only colour.
- Submit disabled until `canSubmit` (no field errors) — never allows a known-invalid command to post.
- Offline submits are visibly banner-flagged so the operator knows the command is queued, never silently dropped.
- Fully server-driven: the same screen renders client / loan / savings / product forms — zero per-entity layout.
