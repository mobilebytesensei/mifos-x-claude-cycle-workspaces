## Screen Intent

Offline recent-search history for field officers — distinct from the live search in M14. Shows the signed-in user's last 50 searched entities (clients, loans, groups, centers) in a Room ring-buffer table, ordered by most recently searched. **Permission gate (§4.7 Tier 3): `requires_permission: READ_CLIENT`, `denied_behavior: gray-out-info-dialog` on row tap and re-run-search actions** — rows are visible but tapping a denied row shows an info dialog ("You don't have permission to open this entity. Contact your manager.") rather than navigating. All reads are offline — no Fineract API calls. Rows are inserted by the live search screens (client-list, m14, loan-detail) when the user selects a result.

## Undo-Delete Interaction

When `delete_row_icon` is tapped for a row (e.g. sr-001 "Aisha Bello"):
1. Row removed from the list immediately (Room delete committed).
2. Snackbar: `"Search removed.  [Undo]"` — 3-second countdown.
3. `pendingDeleteId = "sr-001"`. If **Undo** tapped within 3s: re-INSERT the row with original `searched_at`.
4. After 3s: `pendingDeleteId = null`; deletion is final (no further recovery).

## Accessibility & Density Notes

- `history_row` accessibility_label: `"Open {entityDisplayName} ({entityType}), searched {relativeTime}"`.
- `delete_row_icon` accessibility_label: `"Delete search history entry for {entityDisplayName}"`.
- Undo snackbar is announced via `LiveRegion.POLITE` — screen readers hear "Search removed. Undo available for 3 seconds."
- Entity type chips are not interactive themselves — the tap target is the full row.
- Rows are rendered even when `READ_CLIENT` is denied (gray-out rather than hide) — the history is the user's own data, visible but restricted in navigation.
- `clear_all_button` requires a confirm dialog — destructive intent guard before clearing all 50 entries.
