## Screen Intent

"Powered by Mifos Initiative" product onboarding connection editor. Any Mifos/Fineract organization installs the app, points it at their server (via QR scan or manual entry), and it becomes their branded back-office. **Three entry points**: sign-in screen Scan/Configure buttons; M04 Loan Portfolio "Network settings" tile; M17 Sync & Settings "Network configuration" row. **Two connect paths**: (A) "Use Mifos community demo" — one tap fills the PRIMARY `mifos-bank-2.mifos.community` defaults so evaluators start immediately; (B) "Your organization" — custom base-URL / tenant / username / password + optional QR scan. Save validates (`GET /v1/serverinfo` probe), persists to the encrypted store, swaps `DynamicBaseUrlPlugin`, and forces a `POST /v1/authentication` re-auth. No server permission gate — available to every user (pre-auth and post-auth).

### State: `scanning` — camera QR view

Full-screen camera preview with a scan-target overlay (rounded square crop guide). An in-app `"Waiting for QR code..."` label beneath the overlay. On successful decode of a Mifos config QR, fields auto-fill and state transitions to `editing`. On failure or cancel, a snackbar appears: `"QR code not recognized — please scan a valid Mifos config QR or enter details manually."` and the camera closes back to `idle` or `editing`.

### State: `validating` — connection probe in flight

Form fields disabled; `validate_button` replaced by a circular progress indicator. Label beneath: `"Testing connection to mifos-bank-2.mifos.community..."`. On success (HTTP 200 from `GET /v1/serverinfo`): a teal chip `"Connection verified ✓"` appears; `save_button` becomes enabled; transitions to `editing`. On failure: transitions to `error` with the server error detail.

On success: routes to capability bootstrap (fineract-auth-session authenticated state). On re-auth failure: transitions to `error` (config is persisted; retry offered).

## Accessibility & Density Notes

- `save_button` is `enabled_when: validationResult == VERIFIED` — no premature save path.
- Password field is `input_type: password` — never echoed; bcrypt-hashed before any persistence; value not logged.
- QR password exclusion is intentional for security — on decode the password field remains empty and focused.
- `demo_banner` makes credential pre-filling explicit to the user (no hidden auto-login).
- The `"Reset to demo"` action requires a confirm dialog before overwriting any saved org config — destructive intent guard.
- Inline validation errors are visually beneath the field and carry `contentDescription` for screen readers.
