## Screen Intent

The platform-configuration admin, an entity-tabbed master/detail across five families — **Data Tables** (custom datatable schemas per Fineract entity + columns), **Global Config** (platform switches), **Entity Checks** (mandatory-datatable rules), **External Services** (S3/SMTP/SMS connectors, secrets masked), **Field Config** (per-entity built-in field rules, read-only). Each Register/New/Edit/Toggle is VISIBLE/enabled per the user's exact permission. Schema + config edits are **ONLINE-ONLY** (a half-applied schema is dangerous); rejected commands route to `needs-attention-inbox`; cached datatable schemas keep `dynamic-template-forms` rendering custom fields offline.

## App Shell (resolved from `app-shell.yaml`)

- **Top app bar** — small M3, `surface`, title "Data Tables & Config", menu/back leading.
- **Bottom navigation** — visible as a module root. **Offline banner** — `config-online-only` blocks writes ("connect to change configuration"); catalog readable from cache.

### State: `loading` — config shimmer
Header + config tabs stay; rows render as `shimmer-skeleton`; cached datatable schemas preserved so `dynamic-template-forms` keeps rendering custom fields.

### State: `empty` — tab has no rows
Illustration + tab empty message + a "Register …" / "New …" CTA (only with the matching REGISTER/CREATE permission).

### State: `submitting` — schema/config change (online-only)
A register/deregister/add-column, global-config toggle, entity-check add/remove, or external-service credential edit posts with a "Saving…" / "Submitted for approval" chip. ONLINE-ONLY — offline the control is disabled ("connect to change configuration").

### State: `action-disabled` — permission missing
A user lacking a mutation (e.g. REGISTER_DATATABLE / UPDATE_CONFIGURATION) sees the control disabled with a reason chip; create/register FABs HIDDEN fail-closed.

### State: `error` — fetch/command failed
Server error verbatim (duplicate table name / column-in-use / optimistic-lock / 403 drift) + Retry; rejected commands route to `needs-attention-inbox`; cached schemas stay usable.

## Accessibility & Density Notes

- Schema/config edits ONLINE-ONLY — a half-applied schema is dangerous, so the offline block is explicit, never a silent deferred replay.
- External-service secrets are masked in the list; only a "configured" badge is shown.
- Register/create FABs hidden (fail-closed); meaningful stages disabled-with-reason.
- Deregister/delete are destructive + confirm.
