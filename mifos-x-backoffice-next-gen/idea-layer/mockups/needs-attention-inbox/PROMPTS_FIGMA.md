Two semantic extensions beyond stock M3 matter here: `warning` `#F57C00` for High-priority badges and `warning_strong` `#B45309` for Critical-priority badges (a deeper amber so Critical reads distinctly from High even for a colour-blind viewer, backed by the badge's text label). `success` `#2E7D32` marks the "all caught up" empty-state illustration.

Typography is Roboto throughout, with **Roboto Mono** reserved for tabular/identifier numerics — in this screen that means loan numbers, audit ids, and center/group ids embedded in row subtitles (e.g. "LN-482655", "audit_id 90112", "Center 33") should render in Roboto Mono so they read as data, not prose. ## Section 2: Screen Layouts

This is a **single-screen, five-state** list archetype (`needs-attention-inbox`, ViewModel `NeedsAttentionViewModel`). Canvas is 393×852dp (Pixel 5 portrait reference). **Loading layout.** Vertical scroll layout, light-icon 24dp transparent status bar. The top app bar and the (dimmed, non-interactive) category filter chip row stay fixed at the top so the shell doesn't jump when content resolves. Below that, render two to three shimmer group blocks: each block is a `surface_variant`-filled rounded rectangle (`radius.md`) sized to match the eventual real content — a short "group header" bar (~120×20dp) followed by two to three "row" bars (full-width minus 32dp margin × 64dp height, `radius.md`, 12px vertical gap). No group counts, no item text, and no error strip render in this state. Apply a 1.5s pulse opacity animation (0.6 ⇄ 1.0) to every shimmer block, `standard` easing, looping until the fan-in resolves.

**Content layout — the primary state.** Vertical scroll layout, `section_gap` (24px) between category groups, `row_padding` (12px) inside each row. Render order top-to-bottom: (1) the fixed header + filter-chip row, (2) an **Approvals** group with a group-header band reading "Approvals (2)" in `label_large` on `secondary_container`, followed by 2 item rows; (3) a **Failed syncs** group header "Failed syncs (3)" followed by 3 item rows; (4) an **Overdue tasks** group header "Overdue tasks (2)" followed by 2 item rows; (5) an **Alerts** group header "Alerts (2)" followed by 2 item rows. Each item row is a `surface`-background card with a 1px `outline_variant` border, `radius.md` corners, containing (left-to-right, top-to-bottom): a priority badge (top-left), the item title in `body_medium`/`on_surface`, the item subtitle in `body_small`/`on_surface_variant` with any embedded id in Roboto Mono, and a right-aligned or below-title action control appropriate to that row's category (Approve for approvals, Retry+Discard for failed syncs, Snooze for overdue/alerts). Populate every row with the real demo content from Section 5 below — never a generic "Item 1" placeholder.

**Empty layout.** Centered vertical stack occupying the full content area below the header: a 200dp illustration placeholder region (a stylized checkmark/"all clear" glyph on a `success`-tinted circular background), an `headline_small` "All caught up" title, a `body_medium` "Every source is clear — nothing needs you" subtitle, a `body_small`/`on_surface_variant` "Last synced: 2 minutes ago" caption, and a primary filled "Sync now" button (`primary` fill, `on_primary` label, `radius.xl`) below the caption with 24dp top margin. No group headers or filter chips render as active content in this state (the filter row may remain visible but shows no groups beneath it).

**Resolving layout.** Visually identical to Content, except the ONE row matching the in-flight resolution (e.g. the tapped Failed-syncs row) swaps its action controls for a determinate-or-indeterminate progress indicator plus a short status caption ("Re-enqueuing with fresh idempotency key…"), and that row's background shifts to `surface_variant` with reduced opacity (`opacity.loading`, 0.60) on its action area only — title/subtitle stay fully legible. Every other row in every other group remains fully interactive and unchanged.

**Error layout — two distinct visual treatments.** (a) *Whole-screen error* (only when the local Room read throws before any source contributes): centered vertical stack — an error icon in `error` color, `headline_small` "Couldn't load your inbox" title, `body_medium` explanatory copy, and a primary "Retry" button. (b) *Per-category degrade* (the common case — a single remote source failed): the affected group's header renders normally but its row area is replaced by a single inline strip — an `error`-colored warning icon, a `body_small` message ("Couldn't load approvals"), and a text-style "Retry loading" button — while every other group directly above/below it renders its normal rows. Never conflate these two: a per-category failure must NOT collapse into the whole-screen error layout.

## Section 4: Interaction Patterns

**Navigation transitions.** Tapping an `nai_item` row navigates to the owning module with a `slide_right` 300ms `standard` easing transition: approval rows → M15 approvals-makerchecker detail (keyed by `auditId`); overdue-collections rows → M06 collections (keyed by the entity ref, e.g. `group/58`); overdue-loan or loan-alert rows → M04 loan portfolio (keyed by `loanId`); alert rows → their `deep_link` target (e.g. `m13-scheduler-jobs/12`). Tapping `nai_empty_sync` or a sync-diagnostics alert navigates to M17 sync-settings with the same transition.

**Filtering (no navigation, no refetch).** Tapping a category chip in `nai_category_filters` performs an instant, client-side re-render of `nai_content` to show only that category's group — 150ms `fade_in` crossfade between the full feed and the filtered view. Tapping the already-selected chip again clears the filter and restores all groups.

**Inline resolution flow (Retry / Discard / Approve / Snooze).** Each control transitions ONLY its own row into a locked, in-flight visual (see `resolving` layout in Section 2) — never the whole screen. On success the row either updates in place (Snooze: badge/label unchanged, row simply stops resurfacing after the snooze window) or animates out of its group with the group's count decrementing (Retry once replay eventually succeeds; Discard immediately after confirm; Approve/Reject immediately on success). Use a 300ms `emphasized_decelerate` easing for the row-removal animation.

**Per-category error recovery.** `nai_group_retry` triggers a scoped refetch — only that category's shimmer briefly reappears inline within its own group band (not the whole content area) for the duration of the retry, then either resolves to real rows or remains in the error-strip state.

**Whole-screen error recovery.** `nai_error_retry` resets the entire screen to the `loading` state (full shimmer layout) and re-runs all four sources from scratch — this is the ONLY control that returns the screen to `loading` from a state other than the initial mount.

**Pull-to-refresh.** A circular pull-to-refresh indicator (`primary` tint) at the top of `nai_content`, available in the `content` and `empty` states, triggers the same full fan-in as `nai_error_retry` but without transitioning the visible state to `loading` — existing rows stay visible with a subtle overlay dimming until the refresh completes.

**Confirm dialogs.** `nai_discard` is the only control that opens a modal confirm dialog (Material 3 basic dialog, `surface_container_high` background) requiring the user to pick an explicit ConflictStrategy before any deletion proceeds.

## Section 6: Responsive Rules

**Canvas.** Base canvas 393×852dp (mobile portrait, Pixel 5 reference); 24dp status bar; 48dp gesture nav bar (or 56dp for 3-button nav); safe content area 393×770dp minus the 56dp top app bar and 80dp bottom nav bar.

**Touch targets.** Minimum 44×44dp (`touch_targets.minimum`), comfortable 48dp used for all row action buttons (Retry/Discard/Approve/Snooze), spacious 56dp for the primary Empty/Error state buttons.

**Font scaling.** Support system font scaling 85%–200%; anchor the type scale to `body_medium` (14px); cap body-text line length around 60 characters before wrapping (relevant to the two-line subtitle truncation rule on `nai_item`).

**Theme variants.** Light theme (`colors.light.*`) is canonical/default per `theme_default: light`; dark theme (`colors.dark.*`) is a full M3 tonal flip available for system-default users — swap token values only, never restructure layout between themes.

**Adaptive layout.** Phone portrait: single-column list as specified above. Tablet (600dp+) / desktop (840dp+): the permission-filtered navigation drawer replaces the bottom nav bar (per `app-shell.yaml#drawer`), and the content column may cap at ~600dp centered with additional side padding rather than stretching full-width — group and row structure is otherwise unchanged.

**Offline indication.** Since three of the four sources are CACHE_FIRST_SWR and the fourth (outbox) is local-only, no persistent "offline banner" is required on this screen specifically — cached groups render normally and inline retries queue — but if the project's global offline banner is active elsewhere, it may stack directly below `nai_header` without shifting any group's vertical position by more than the banner's own height.
