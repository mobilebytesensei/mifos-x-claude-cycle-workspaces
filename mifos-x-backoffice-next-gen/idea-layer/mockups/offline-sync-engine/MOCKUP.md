## Screen Intent

The outbox / batch-replay / delta-pull console — the foundation engine every mutating command routes through. Lists pending outbox commands (idempotency key, action, entity, age), drains them via `POST /v1/batches` (per-command PENDING→RETRYING→SUBMITTED, exactly-once), and hydrates fresh state via delta-pull. Failed commands surface with the server error and a "Review N failed" route into `needs-attention-inbox`. Offline, commands stay queued under a persistent banner.

## App Shell (resolved from `app-shell.yaml`)

- **Top app bar** — small M3, `surface`, title "Sync Engine", back leading (foundation console; usually reached via M17 or a "review failed" link).
- **Bottom navigation** — suppressed on this console. **Offline banner** — persistent "N queued · will sync when online" (captive-portal aware).

## Accessibility & Density Notes

- Per-command PENDING→RETRYING→SUBMITTED progress is textual, not colour-only.
- Failed commands are always surfaced + routed to `needs-attention-inbox`, never silently dropped.
- Exactly-once semantics: an idempotency-keyed command replays without double-applying — the console never double-drains a row.
- Ids/keys/counts in Roboto Mono for legible outbox scanning.
