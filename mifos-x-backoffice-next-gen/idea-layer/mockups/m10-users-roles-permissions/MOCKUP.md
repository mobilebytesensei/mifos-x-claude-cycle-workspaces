## Screen Intent

The authorization admin: a **Users tab**, a **Roles tab**, and the **role→permission grid editor**. An authoriser holding `PERMISSIONS_ROLE` can edit the grid and toggle maker-checker per action; a READ_USER/READ_ROLE-only operator sees the rosters with the grid cells read-only and every mutating control hidden/disabled. User/role create/edit/enable/disable queue to the offline outbox; the **authorization config itself (grid + maker-checker) is ONLINE-ONLY** (never deferred), and on save the runtime capability cache is invalidated. A 403 triggers the permission-drift re-fetch and prunes denied controls live.

### State: `loading` — roster/grid shimmer
Header + tabs stay; user/role rows + grid render as `shimmer-skeleton` (CACHE_FIRST_SWR).

### State: `empty` — no users/roles
Illustration + a Create CTA present only with the matching CREATE_USER / CREATE_ROLE.

### State: `submitting` — user/role command queuing
A user/role create/edit/enable/disable queues to the outbox (idempotency key) → POST /v1/users / PUT /v1/roles/{id} — "Submitted for approval" when maker-checkerable.

### State: `saving` — grid persist (online-only)
The edited role→permission grid or a maker-checker toggle persists ONLINE-ONLY via PUT /v1/roles/{id}/permissions / PUT /v1/permissions (never deferred); on success the runtime capability cache is invalidated.

### State: `error` — fetch/submit failed
400 validation / 403 authorization / 409 conflict + Retry; a 403 re-fetches the PermissionSet (drift protocol) and prunes denied controls live.

## Accessibility & Density Notes

- Grid cells are `PERMISSIONS_ROLE`-gated checkboxes with clear checked/unchecked + maker-checker (MC) sub-toggle; read-only cells visibly non-interactive.
- Authorization config is ONLINE-ONLY — never a silent deferred replay of a permission change.
- A 403 prunes denied controls live via the drift protocol — the UI never shows an action the server will reject.
- Enabled/disabled state carries text, not colour alone.
