## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to signin)
- 403 -> NoAuthorization -> permission-capability-engine drift refresh + re-resolve (READ_CLIENT for reads, per-command gate for the action)
- 404 -> NotFound error (deleted / wrong clientId -> empty not-found panel)
- 409 -> Optimistic-lock / status conflict -> aggregate refreshed, action re-offered
- 500 -> Server error (retryable; error state + Retry)

Notes:
- `get_client` + `get_client_accounts` are reads — CACHE_FIRST_SWR: the profile opens instantly from cache and a background revalidate refreshes it (stale badge), so the client works offline. An accounts-only failure degrades to an inline retry strip, never a whole-screen error.
- `client_lifecycle_command` is enqueued through the offline outbox with a durable UUIDv4 Idempotency-Key and replayed all-or-nothing via `POST /v1/batches` — exactly-once. Only the `?command=` members valid for the current status AND held by the PermissionSet are exposed in the action bar.
