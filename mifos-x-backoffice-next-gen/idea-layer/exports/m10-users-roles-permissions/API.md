## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to signin) / permission drift (403 -> permission-refresh protocol, denied controls pruned live)
- 404 -> NotFound error
- 409 -> Conflict (optimistic-lock on a grid save — the grid changed server-side since load; reload-then-resave, edit preserved)
- 422 -> Validation error (server body shown against the offending field)
- 500 -> Server error (retryable)

**Write policy**: user/role writes (create_user, update_user, create_role, toggle_role_status) are queued through the offline-sync-engine durable outbox with an `Idempotency-Key` (exactly-once resubmit); a maker-checkerable command returns 2xx + commandId with empty changes (Submitted-for-approval), and a rejected submission routes to needs-attention-inbox. The role→permission grid save (update_role_permissions) and maker-checker config (update_permission_maker_checker) are **ONLINE-ONLY** — an authorization change is never deferred to the offline queue; saving the grid invalidates the runtime PermissionSet cache (permissions_raw / permission_fingerprint / capability_map) so affected users re-resolve their capability surface on next login.
