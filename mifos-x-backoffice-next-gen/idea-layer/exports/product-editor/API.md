## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to signin)
- 403 -> NoAuthorization -> permission-capability-engine drift refresh + re-resolve (READ_LOANPRODUCT / CREATE|UPDATE_LOANPRODUCT)
- 400 -> Validation error -> server errors[] mapped back onto the offending field by parameterName
- 409 -> Optimistic-lock conflict -> product refreshed, save re-offered
- 500 -> Server error (retryable; error state + Retry)

Notes:
- `get_product` + `get_product_template` are reads — CACHE_FIRST_SWR: every field, bound and option comes from the template so the form always matches the server's product schema and drafts offline. (Savings products use /v1/savingsproducts/{id}.)
- `save_product` is enqueued through the offline outbox with a durable UUIDv4 Idempotency-Key and replayed all-or-nothing via `POST /v1/batches` — exactly-once. PUT edits an existing product; a create posts to `POST /v1/loanproducts` gated on CREATE_LOANPRODUCT.
