## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to tenant signin)
- 403 -> NoAuthorization -> permission-drift protocol: password-less role-permission refresh + fingerprint compare + re-resolve (not a crash)
- 404 -> NotFound error
- 422 -> Validation error
- 500 -> Server error (retryable; error state + Retry)

Notes:
- `authenticate` is the sole runtime authorization input — its `permissions: Collection<String>` are normalized verbatim into the PermissionSet (never lowercased, split, or umbrella-expanded).
- `get_role_permissions` is the password-less fallback for the 403 drift protocol — the union across the user's enabled roles rebuilds the PermissionSet without re-prompting for the password; an unchanged sha256 fingerprint is a no-op, a changed one triggers an atomic swap + re-resolve.
- `get_permissions_catalog?makerCheckerable=true` returns the subset whose commands require maker-checker approval, driving the pre-flighted "requires approval" badges.
