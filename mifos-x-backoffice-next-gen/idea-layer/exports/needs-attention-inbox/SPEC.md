- **has_offline_cache** — the local outbox (`draft_outbox`) is the offline system-of-record for failed replays (read via a Room Flow, no HTTP GET); the three remote sources (maker-checker, collections, notifications) read CACHE_FIRST_SWR so the inbox renders fully offline.

## Flow Logic (5 decisions)

| Decision | Condition | True Path | False Path | Impl |
|----------|-----------|-----------|------------|------|
| Aggregation result | fan-in returns ≥1 item across ≥1 permitted category | content (grouped + ranked) | empty ("all caught up" + Sync now) | fold four permission-filtered sources (Room Flow + 3 CACHE_FIRST_SWR fetches) → NeedsAttentionScreenState |
| Source vs hard failure | a single remote source errors | content + per-group retry strip (`fallback_cache`, rest still renders) | error ONLY when the local Room read throws before any source contributes | per-source `error_state=content` (degrade); local outbox read failure `error_state=error` |
| Category permission gate | user holds the category's permission (`canCheck` / `READ_COLLECTIONSHEET`) | category contributes rows | category omitted entirely from the feed | PermissionEvaluator gate applied per source at aggregation time |
| Retry replay permission | queued command's permission still valid on replay | re-enqueue w/ fresh idempotency key → POST /v1/batches | surface BLOCKED_PERMISSION_REVOKED (never silently dropped) | replay revalidates per-command permission before POST /v1/batches |
| Approve authorization | user `canCheck(action,entity)` or holds `CHECKER_SUPER_USER` | inline Approve/Reject shown → POST /v1/makercheckers/{auditId}?command=approve\|reject | no Approve control rendered on that row | per-entry client gate layered above the server-side checker scope |
