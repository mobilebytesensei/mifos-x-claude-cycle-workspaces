## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error / session expired -> permission-capability-engine re-auth (replay revalidates permission)
- 403 -> NoAuthorization (delta feed requires READ_AUDIT)
- 404 -> NotFound error
- 422 -> Validation error (rejected batch row -> needs-attention-inbox)
- 500 -> Server error (retryable; error state + Retry all)

Notes:
- `replay_batch` is the offline-sync keystone: `enclosingTransaction=true` = AllOrNothing (whole batch commits or rolls back); each enclosed request carries a durable `Idempotency-Key` header per outbox entry so a retry after a partial network failure never double-posts. `enclosingTransaction=false` = Independent (collection-sheet rows may partially succeed; failed rows route to needs-attention).
- `delta_changelist` is a safe GET: the `makerDateTimeFrom` watermark returns only changes after the last sync (delta, not snapshot), scoped by `officeId` to the user's office/portfolio; the response advances each entity cache's FetchedAt watermark so CACHE_FIRST_SWR reads know what to revalidate.
- Money-movement commands (REPAYMENT_LOAN, DEPOSIT_SAVINGSACCOUNT, SAVECOLLECTIONSHEET_*) are the outbox payloads replayed inside the /v1/batches enclosed requests. Admin/accounting/roles mutations are NEVER queued — online-only + maker-checker.
