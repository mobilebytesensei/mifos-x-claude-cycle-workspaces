## Error Handling

All endpoints follow standard error mapping:
- 400 -> Validation error (invalid cron expression on update_job)
- 401 -> Auth error (redirect to signin)
- 403 -> NoAuthorization -> permission-capability-engine drift refresh + re-resolve (not a crash)
- 409 -> Conflict (job already running / run failed to start)
- 500 -> Server error (retryable; error state + Retry)

- `list_jobs`, `get_job_run_history`, `get_scheduler_status`, `get_business_date` are reads — CACHE_FIRST_SWR so the roster + run history + scheduler status + business date render offline; `get_job_run_history` is offset/limit paged (`{ totalFilteredRecords, pageItems[] }`).
