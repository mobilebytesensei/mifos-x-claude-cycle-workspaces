## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to signin)
- 403 -> NoAuthorization -> permission-capability-engine drift refresh + re-resolve (not a crash)
- 404 -> NotFound error
- 409 -> Optimistic-lock conflict (e.g. activating a campaign whose template was deleted) -> needs-attention-inbox
- 422 -> Validation error
- 500 -> Server error (retryable; error state + Retry)

Notes:
- `list_*`, `get_*` are reads — CACHE_FIRST_SWR so the campaign list, template library and hooks render instantly offline and background-revalidate when stale.
- `create_*`, `update_*`, `activate_*`, `close_*`, `save_email_config` are enqueued through the offline outbox with a durable idempotency key and replayed exactly-once (`POST /v1/batches`) — a campaign never double-activates.
- Command results are maker-checker aware: a `commandId` without a `resourceId` = submitted-for-approval (status NOT optimistically flipped) and routes to M15 (Approvals).
- `save_email_config` password is stored via secure storage and never returned by `get_email_config` nor logged.
