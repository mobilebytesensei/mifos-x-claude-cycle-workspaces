## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to signin)
- 403 -> NoAuthorization -> permission-capability-engine drift refresh + re-resolve; the denied pane/report is pruned live (not a crash)
- 404 -> NotFound error
- 422 -> Validation error (report param validation on run_report)
- 500 -> Server error (retryable; error state + Retry)

Notes:
- All five endpoints are READS — nothing on this surface mutates. `list_reports`, `global_search`, `get_audits`, `get_audit_search_template` and a same-params `run_report` are CACHE_FIRST_SWR so a prior catalog / result / hit set / audit page renders offline; a fresh `run_report` runs online.
- `list_reports` is client-filtered to reports the operator may run (READ_{reportName} / REPORTING_SUPER_USER); `run_report` is gated per-report; `get_audits` + `get_audit_search_template` require READ_AUDIT; `global_search` carries no permission gate (any authenticated operator). All panes are server-scoped to the operator's office hierarchy.
- Export is a LOCAL CSV/PDF render (FileKit) handed to the OS share sheet — not a server call.
