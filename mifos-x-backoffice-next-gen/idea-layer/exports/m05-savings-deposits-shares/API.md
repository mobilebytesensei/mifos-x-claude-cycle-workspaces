## Error Handling

All endpoints follow standard error mapping:
- 401 -> Auth error (redirect to signin)
- 403 -> NoAuthorization / permission-drift (route to permission-capability-engine, refreshPermissions())
- 404 -> NotFound error
- 409 -> Optimistic-lock conflict (route rejected command to needs-attention-inbox)
- 422 -> Validation error
- 500 -> Server error (retryable)

Money-movement commands (savings_transaction, *_lifecycle, account_transfer, standing_instruction) are outbox payloads carrying a DURABLE idempotency key and replayed exactly-once via `POST /v1/batches` — never a direct online post that could double-post. Maker-checker tenants return a 2xx with commandId + empty changes (PENDING_APPROVAL). Every command POST carries `dateFormat` + `locale` alongside its date field (Fineract cross-cutting contract §0).
