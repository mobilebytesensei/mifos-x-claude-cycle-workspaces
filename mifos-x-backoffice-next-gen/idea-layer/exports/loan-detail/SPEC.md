## Capabilities

### has_ui
Compose detail screen: a loan summary header + tabbed body (Schedule · Transactions · Details) + a permission-gated lifecycle action bar.

### has_offline_cache
The loan aggregate reads CACHE_FIRST_SWR through Store5 into the `loan_cache` Room table; the loan opens fully offline with a stale-refresh badge.

### has_flow
Entered from the M01 dashboard repayment tile / M04 loan-portfolio list / needs-attention-inbox drill-in; loading → content/empty/error, the client link drills into client-detail-360.

### requires_auth

- **Errors**: loan_not_found (retry=false; empty state — the loanId resolved to no account, shows a not-found panel with a back affordance), loan_load_failed (retry=true; error state — no usable cache, Retry re-reads the aggregate), action_not_permitted (retry=false; 403 — action hidden, permission-capability-engine drift refresh + re-resolve), repayment_post_failed (retry=true; surfaced inline, entry stays queued in the outbox for replay)

## Flow Logic (6 decisions)

| Decision | Condition | True Path | False Path | Impl |

| Loan resolves | the loan aggregate resolves (cache-first) with associations | content | (see empty/error) | Store5 CACHE_FIRST_SWR over `GET /v1/loans/{loanId}` |
| Not found | the loanId resolves to no account (deleted or wrong id) | empty (not-found panel + back) | content | server-side 404 on the aggregate read |
| Load hard-fail | the loan failed to load and no cache is available | error (message + Retry) | content | `GET` failure with an empty `loan_cache` |

| Error retry | "Retry" is tapped from the error state | loading (re-reads the aggregate) | error | `retry` → `GET /v1/loans/{loanId}?associations=all` |
