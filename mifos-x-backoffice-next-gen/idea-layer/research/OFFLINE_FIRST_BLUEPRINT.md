# Offline-First Architecture Blueprint — Fineract feature on openMF/kmp-project-template (audit)

> Verified against the local checkout (`workspaces/mifos-x/kmp-project-template/source/kmp-project-template/`, template ≥ v2.6.0, base namespace `kpt`, Room 3, Store5 `org.mobilenativefoundation.store.store5`, Ktorfit, Koin). All names are REAL unless marked **NEW**.

## 1. Module map

```
cmp-{android,ios,desktop,web}  platform shells   ·   cmp-shared  initKoin + workers
cmp-navigation                 root NavHost + KoinModules.allModules
sync/                          background sync (worker-kmp CoroutineWorker)
core-base/*                    FRAMEWORK — never edit in a fork
core/*                         fork-owned integration seam (Fineract code goes here)
feature/*                      one module per user-facing feature
```

- **`core-base/store`** (framework, upgrade-stable): `StoreFactory`(`createStore`/`createMutableStore`/`createOfflineStore`/`createMemoryStore`/`createScreenWithMutation`), `DefaultValidator.withTtl()`, `DecisionEngine.decide(StoreData,NetworkStatus)→ScreenState`; `ScreenState`(6 variants: `Loading/Content(data,freshness,fetchedAt)/NoNetwork(isCaptivePortal)/Error/Empty/Unauthenticated`); `Store.asScreenStream(...)` (**default `FetchPolicy.CACHE_FIRST_SWR`** — emit cache instantly, background-revalidate only when `FreshnessBands` says Stale); `FetchPolicy{NETWORK_WITH_CACHE,NETWORK_ONLY,CACHE_ONLY,PERIODIC,CACHE_FIRST_SWR}`; paging `PageKey(page,pageSize,query)`+`Store.asPagingScreenStream(...)`; **submit** `SubmitHandler`/`DraftSubmitHandler`/`SubmitOutbox<P>`+`SubmitOutboxEntry`+`SubmitOutboxStatus{PENDING,RETRYING,SUBMITTED,FAILED}`/`OfflineSubmitSyncer`/`BatchSubmitHandler`+`BatchSubmitMode{AllOrNothing,Independent}`+`BatchResult`/`IdempotencyKey.generate()`/`RetryPolicy`; `error/categorize()→ErrorCategory`.
- **`core-base/ui`**: `ScreenContent`, `PagingScreenContent`(+LoadMore), `MutationScreenContent`, `IndependentCardLayout`+`aggregateDashboardProgress()`, `FreshnessIndicator`/`RefreshStateChip`; MVI bases `BaseViewModel<State,Event,Action>`, `BaseSubmitMutationViewModel`, `BaseDraftMutationViewModel<T,R>`.
- **`core-base/network`**: `setupDefaultHttpClient(baseUrl, authRequiredUrl, defaultHeaders, basicCredentialsProvider/bearerTokensProvider+bearerRefreshProvider(mutex), certificatePinConfig, corsProxy/proxiedHosts, dynamicUrlProvider)`, `DynamicBaseUrlPlugin`.
- **`core-base/database`**: `AppDatabaseFactory` + **Room invalidation bridge** `RoomChangeBus.notify("table")`, `daoFlow("table"){dao.observeX()}`, `notifyingWrite("table"){dao.upsert()}` (absorbs Room 3 alpha05 wasmJs fan-out gap).
- **`core/*` (fork-owned):** `core/model` (@Serializable domain), `core/network` (Ktorfit APIs+DTOs+`NetworkModule`), `core/database` (Room `AppDatabase` + per-domain entity/dao/mapper + infra tables `framework_submit_drafts`/`DraftEntity`,`BookkeeperEntity`,`FetchedAtEntity`), **`core/store`** (THE seam: `AppStoreRegistry`, `AppScreenStateDefaults`, `AppErrorMapper`, `StoreModule`, `StoreCacheManager`, per-domain `provide*Store()`), `core/data` (repositories + `Synchronizer`+`changeListSync`/`snapshotSync`, `RoomSubmitOutbox`/`RoomBookkeeper`/`RoomFetchedAtRepository`, `RepositoryModule`+`OutboxQualifiers`), `core/domain` (pure use-cases), `core/auth` (`AuthProvider` seam, default `NoOpAuthProvider`), `sync/` (`DataSyncWorker` implements `Synchronizer`).

**A–L slot layers per feature:** A `core/model` · B `core/network` api+dto · C `core/database` entity+dao+mapper · D `core/store` Store + `AppStoreRegistry` row · E `core/data` repository + `Syncable` · F `core/domain` (optional) · G `feature/{f}` ViewModel · H `feature/{f}` Screen · I navigation · J DI module · K `cmp-navigation` includes + graph · L `sync` registration.

## 2. Offline-first READ path — `GET /clients`

`Fetcher(Ktorfit) → Store5 → SourceOfTruth(Room) → StoreData → asScreenStream() → DecisionEngine → ScreenState → ScreenContent`

- **B** `FineractClientApi{@GET("v1/clients") getClients(offset,limit):ClientPageDto}` registered in `NetworkModule` via `Ktorfit.Builder().httpClient(httpClient(setupDefaultHttpClient(baseUrl, defaultHeaders=mapOf("Fineract-Platform-TenantId" to tenant), basicCredentialsProvider={...}))).build()`.
- **D** `provideClientsStore(api,networkMonitor,dao): Store<Unit,List<Client>>` = `StoreFactory.createStore(fetcher=Fetcher.of{...api.getClients(0,200).map{it.toDomain()}}, sourceOfTruth=SourceOfTruth.of(reader={daoFlow("fineract_clients"){dao.observeAll()}.map{...}}, writer={_,c-> notifyingWrite("fineract_clients"){dao.upsertAll(...)}; validator.markFresh()}, delete/deleteAll), validator=DefaultValidator.withTtl(AppStoreRegistry.Ttl.CLIENTS))`. **Two non-obvious contracts: (a) `validator.markFresh()` MUST follow every successful write or TTL never starts; (b) SoT reader/writer wrapped in `daoFlow{}`/`notifyingWrite{}`.** Register in `AppStoreRegistry` + `StoreModule` `single(...)` + `mgr.register(...)` in the logout block.
- **E** `ClientsRepositoryImpl.clientsStream(scope,fetchPolicy) = clientsStore.asScreenStream(key=Unit, networkMonitor, fetchedAtRepository, cacheKey="fineract:clients", scope)` (default `CACHE_FIRST_SWR`).
- **G** `ClientsListViewModel: BaseViewModel<...>` exposes `screenState:StateFlow<ScreenState<List<Client>>>` (`stream.state.combineContent{filter}.emptyIfContent{}`) + `freshness`. `handleAction: Retry→stream.retry(), Refresh→stream.refreshFresh()`.
- **H** `ScreenContent(state, onRetry){ clients -> LazyColumn{items(clients){ClientRow(it)}} }` — renders ALL 6 states free (animated, captive-portal, reconnect auto-refresh, lastContent preservation, a11y). **Screen has ZERO state-handling code.** Paginated variant: `Store<PageKey,List<Client>>` (`offset=page*pageSize` ≙ Fineract paging) + `asPagingScreenStream` + `PagingScreenContent`.

## 3. Offline-first WRITE path (outbox) — POST repayment / collection sheet

Three tiers:
- **Tier 1 `SubmitHandler`** (online, no durability): `viewModelScope.submitHandler<R>()→submit{repo.postRepayment(p)}→SubmitState.Idle→Submitting→Submitted/Failed`. Invalidate read cache on success. Screen: `MutationScreenContent`.
- **Tier 2 `DraftSubmitHandler`+`RoomSubmitOutbox`+`OfflineSubmitSyncer`** (the canonical Fineract-repayment path): ViewModel extends `BaseDraftMutationViewModel<RepaymentPayload,R>(formKey="loan_repayment", uniqueKey=loanId, autoSaveDraft=true)` (multi-pending: N repayments coexist as N PENDING drafts). `RoomSubmitOutbox<P>` serializes the @Serializable payload to `framework_submit_drafts` (`PENDING→RETRYING→SUBMITTED|FAILED`, idempotent upsert per `(formKey,uniqueKey)`). **Each payload type gets its own qualifier binding** (`OutboxQualifiers.Repayment` — Koin indexes by raw type; `RepositoryModuleVerifyTest` enforces parity). `OfflineSubmitSyncer` (app-scoped, edge-triggers on `NetworkStatus`): `getAllPending()→markRetrying→submitBlock→markSubmitted/markFailed`; per-entry failures never abort the batch. Resume UX `DraftResumeBanner`; "N pending sync" badge. Logout→`clearAll()`; start→`pruneExpiredDrafts()` (30d, PENDING never pruned).
- **Tier 3 batch+idempotency (≙ `POST /batches`)**: `BatchSubmitHandler.submitBatch(payloads,idempotencyKey,submitBlock)` with `AllOrNothing` (≙ `enclosingTransaction=true`) or `Independent` (collection-sheet rows may partially succeed) → `BatchResult(total,succeeded,failed,failures[(index,t)],aborted)`. `IdempotencyKey.generate()` = UUIDv4, reused on retries → attach as Fineract `Idempotency-Key`. **⚠ CAVEAT: idempotency key is in-memory only today; `SubmitOutboxEntry.idempotencyKey` exists but the Room-v11 persist migration is deferred — a crash between save & replay mints a new key → double-post risk.** `MutableStore`+`Bookkeeper` (`createMutableStore(fetcher,sot,converter,updater,bookkeeper,validator,conflictStrategy)`) = the write-back path for **entity-shaped edits** (optimistic local + back-fill); use the **outbox** for **command-shaped mutations** (repayment, collection sheet). `ConflictStrategy` accepted but currently informational — resolve manually inside `Updater`.

## 5. Fit notes — maps cleanly vs NEW infra

**Maps cleanly onto shipped patterns:** tenant header (`setupDefaultHttpClient defaultHeaders`), delta-pull (`Synchronizer.changeListSync` — its KDoc literally names Fineract: *"Fineract's lastModifiedSince matches this shape"*), offline reads w/ staleness (`CACHE_FIRST_SWR`+`FreshnessBands`+`RoomFetchedAtRepository`), offline-queued mutations (`DraftSubmitHandler`+`RoomSubmitOutbox`+`OfflineSubmitSyncer`), batch replay (`BatchSubmitHandler.AllOrNothing`≙`POST /batches enclosingTransaction`), paginated lists (`PageKey.offset`≙Fineract `offset/limit`), field-officer dashboard (`IndependentCardLayout`), logout hygiene (`clearAll()`/`pruneExpiredDrafts()`), auth session (`AuthProvider` seam + `ScreenState.Unauthenticated`).

**Needs NEW infrastructure (the 5 build items):**
1. **Dynamic template-driven forms** — Fineract `GET /{entity}/template` field-sets. Template ships only statically-typed Compose forms. NEW: form-schema model + renderer composable; `JsonObject`-backed payload persists through outbox unchanged; cache template JSON in a `CACHE_FIRST_SWR` Store for offline forms.
2. **Permission-gated navigation** — `AuthProvider` models session not authorization; nav graphs register unconditionally. NEW: `PermissionsStore` (over auth response / `/permissions`, `CACHE_ONLY`-readable offline) + `PermissionEvaluator` + route/action gate in `cmp-navigation`. **(= PERMISSION_SCOPE_MODEL.md)**
3. **Durable idempotency** (sharpest financial-correctness gap) — persist `idempotency_key` column on `DraftEntity`, generate at draft-save, send on first submit + every retry. Same migration unlocks parked `RetryPolicy` backoff (`attemptCount`,`nextRetryAt`).
4. **Needs-Attention conflict inbox** — `SubmitOutboxStatus.FAILED`+errorMessage exist but no cross-formKey "all failed" query, no triage screen; `ConflictStrategy` declared-not-wired. NEW: `DraftDao.observeAllFailed()` + `feature/needs-attention` (a `createOfflineStore` over the drafts table) with Retry/Edit/Discard + explicit conflict resolution in `Updater` blocks.
5. **Per-entity Fineract delta adapters** — `changeListSync` is the algorithm; map Fineract's `lastModifiedSince`/audit change-feed per entity family (delta vs snapshot). `DataSyncWorker.awaitAll` = partial-failure-full-retry → consider per-adapter isolation.

> **Bottom line:** `core-base/store` + `core/store` already IS an offline-first Fineract client skeleton — reads, queued writes, batch replay, and delta sync are shipped + showcased. Genuinely new work = the 5 items above.
