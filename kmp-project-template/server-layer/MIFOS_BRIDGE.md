# Mifos Bridge — Server Layer Integration

> How this KMP project connects to Fineract APIs via the Mifos MCP server.
> This doc is the consumer-side reference for `/mifos-bridge`.

---

## Overview

This project uses **Mifos MCP** (`mcp-mifosx`) as its backend API layer. The MCP server wraps Apache Fineract REST APIs as MCP tools that Claude can invoke directly.

When this project needs an API:
1. `/mifos-bridge` checks if Fineract has the API
2. If yes but MCP tool missing → adds Python tool to `mcp-mifosx`
3. If API doesn't exist in Fineract → extends via datatables
4. Returns API contract to this project's server-layer

---

## Two-Path Resolution

### Path 1: API Exists in Fineract Sandbox

```
Consumer needs API (e.g., "update_group")
    │
    ▼
Check Fineract Sandbox (Swagger / live endpoint)
    │  API found: PUT /groups/{groupId}
    │
    ▼
Check MCP Tools
    │
    ├── Tool EXISTS → [NATIVE]
    │   └── Write to this project:
    │       server-layer/API_CONTRACT.yaml (endpoint signature)
    │       server-layer/API.md (documentation)
    │       client-layer/ (DTOs + Services generated by /implement)
    │
    └── Tool MISSING → [TIER 1]
        └── Add full CRUD Python tool to mcp-mifosx:
            1. Generate tools/domains/{domain}.py
            2. Register in mcp_server.py
            3. 4-GATE APPROVAL (user reviews code + tests)
            4. Test against sandbox
            5. Write to this project (same as NATIVE above)
```

### Path 2: API Does NOT Exist in Fineract Sandbox

```
Consumer needs API (e.g., "schedule_meeting")
    │
    ▼
Check Fineract Sandbox
    │  API NOT found — no meeting endpoint exists
    │
    ▼
Check Datatable CRUD Tools in MCP
    │
    ├── CRUD tools MISSING → add 5 foundation tools first (one-time)
    │   create_datatable, get/create/update/delete_datatable_entry
    │
    └── CRUD tools EXIST
        └── [TIER 2]
            1. Design datatable schema (name, columns, apptable)
            2. Write API signature for the custom endpoint
            3. Create datatable on Fineract via MCP CRUD tool
            4. Generate domain Python tools using datatable CRUD
            5. 4-GATE APPROVAL (user reviews schema + code + tests)
            6. Test against sandbox
            7. Write to this project:
               server-layer/API_CONTRACT.yaml (endpoint signature)
               server-layer/API.md (documentation)
               client-layer/ (DTOs + Services generated by /implement)
```

## API Contract Format

After `/mifos-bridge` resolves gaps, it writes `API_CONTRACT.yaml` here:

```yaml
# server-layer/API_CONTRACT.yaml
_generated_by: /mifos-bridge
_generated_at: 2026-05-01T12:30Z
_mcp_server: mifos

endpoints:
  # NATIVE — Fineract API + MCP tool both exist
  - name: get_group
    source: native
    mcp_tool: mcp__mifos__get_group
    method: GET
    path: /groups/{groupId}
    path_params:
      - {name: groupId, type: Int, required: true}
    response:
      type: GroupResponse
      fields:
        - {name: id, type: Int}
        - {name: name, type: String}
        - {name: status, type: GroupStatus}
        - {name: clientMembers, type: "List<ClientSummary>"}
    kotlin_mapping:
      service: GroupService
      method: getGroup(groupId: Int): GroupResponse
      dto: GroupDto -> GroupModel

  # TIER 1 — Fineract API exists, MCP tool was added
  - name: update_group
    source: tier1_mcp_added
    mcp_tool: mcp__mifos__update_group
    method: PUT
    path: /groups/{groupId}
    path_params:
      - {name: groupId, type: Int, required: true}
    body:
      - {name: name, type: String, required: false}
      - {name: externalId, type: String, required: false}
      - {name: staffId, type: Int, required: false}
    response:
      type: UpdateResponse
      fields:
        - {name: resourceId, type: Int}
    kotlin_mapping:
      service: GroupService
      method: updateGroup(groupId: Int, request: UpdateGroupRequest): UpdateResponse
      dto: UpdateGroupRequestDto -> UpdateGroupRequest

  # TIER 2 — Fineract API missing, datatable extension
  - name: schedule_meeting
    source: tier2_datatable
    datatable: dt_group_meetings
    mcp_tool: mcp__mifos__schedule_meeting
    method: POST
    path: /datatables/dt_group_meetings/{groupId}
    path_params:
      - {name: groupId, type: Int, required: true}
    body:
      - {name: meeting_date, type: String, format: "yyyy-MM-dd", required: true}
      - {name: meeting_type, type: String, enum: [regular, special, emergency]}
      - {name: location, type: String, maxLength: 200}
      - {name: notes, type: String}
    response:
      type: CreateResponse
      fields:
        - {name: resourceId, type: Int}
    kotlin_mapping:
      service: MeetingService
      method: scheduleMeeting(groupId: Int, request: ScheduleMeetingRequest): CreateResponse
      dto: ScheduleMeetingRequestDto -> ScheduleMeetingRequest

datatables_created:
  - name: dt_group_meetings
    apptable: m_group
    columns: [meeting_date, meeting_type, location, notes, status]
```

## How /implement Consumes This

When `/implement` runs for this project:

1. **Server layer**: Reads `API_CONTRACT.yaml` → generates/updates `API.md`
2. **Client layer**: Reads `kotlin_mapping` → generates DTOs + Services
3. **Feature layer**: ViewModels inject Services from client-layer

```
API_CONTRACT.yaml
    │
    ├─→ server-layer/API.md (endpoint documentation)
    │
    ├─→ client-layer/
    │   ├─ dto/GroupDto.kt, MeetingDto.kt
    │   ├─ model/GroupModel.kt, MeetingModel.kt
    │   ├─ mapper/GroupMapper.kt, MeetingMapper.kt
    │   └─ service/GroupService.kt, MeetingService.kt
    │
    └─→ feature-layer/
        └─ viewmodel/GroupViewModel.kt, MeetingViewModel.kt
```

## Automatic Bridge (inside `/idea-plan`)

The bridge runs **automatically** — no separate command needed. When `/idea-plan` detects this is a mifos-x project (`backend.provider: fineract`), it adds Phase 3.5:

```
/idea-plan
├─ Phase 1-3: Design screens & flows (normal)
│
├─ Phase 3.5: MIFOS BRIDGE (AUTO)
│   ├─ Extract API needs from all screens
│   ├─ Check Fineract Sandbox → Check MCP tools
│   ├─ TIER 1: Add missing MCP tools (user approves)
│   ├─ TIER 2: Design datatables + tools (user approves)
│   ├─ Write API_CONTRACT.yaml to this project
│   └─ Update MCP_CAPABILITIES.yaml
│
├─ Phase 4-5: Enrich & Export (real API bindings)
└─ Phase 6: Approve → /implement reads contract
```

**User only runs**: `/idea-plan` → approve gates when prompted → `/implement`

### Config

```yaml
# idea-layer/idea-plan.yaml
backend:
  provider: fineract
  mcp_server: mifos
  bridge: auto          # auto | manual | disabled
  capabilities: ../../mcp-mifosx/server-layer/MCP_CAPABILITIES.yaml
  approval_gate: true   # RULE-MIFOS-BRIDGE-001 enforced
```

| Mode | Behavior |
|------|----------|
| `auto` | Bridge runs inside `/idea-plan` and `/idea export` automatically |
| `manual` | Must run `/mifos-bridge` explicitly |
| `disabled` | No bridge, manual API management |
